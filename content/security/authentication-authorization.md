# 인증과 인가: 계정·세션·접근 제어

> **TL;DR**
>
> 인증은 누구인지 확인하고, 인가는 그 주체가 특정 자원에 특정 작업을 해도 되는지 판단합니다. 로그인 이후에도 서버는 요청마다 권한과 세션 상태를 확인해야 합니다.

AI 작성 해설

## 인증과 인가의 차이

도서관 회원증 확인은 인증, 해당 자료를 대출할 수 있는지 판단하는 것은 인가에 해당합니다. 웹에서도 로그인 성공과 관리자 기능 접근은 별개의 결정입니다. 공개 자료는 로그인 없이 읽도록 인가할 수도 있습니다.

| 개념 | 질문 | 입력과 결과 |
|---|---|---|
| 식별 Identification | 누구라고 주장하는가? | 계정명 제출 |
| 인증 Authentication | 그 주장을 믿을 근거가 있는가? | 인증 수단 검증 후 주체 확정 |
| 인가 Authorization | 이 작업을 허용하는가? | 주체·자원·행동·맥락으로 허용 여부 결정 |
| 감사 Auditing | 어떤 결정과 작업이 있었는가? | 행위자·대상·시간·결과 기록 |

## 인증 수단과 계정 복구

비밀번호는 지식 기반, 보안 키는 소유 기반 인증 수단입니다. MFA는 서로 다른 종류의 요소를 결합합니다. 비밀번호와 보안 질문 두 개를 사용하는 것은 독립된 두 요소를 사용하는 것과 다릅니다. 패스키는 공개키 기반 인증을 사용하며 사이트에 비밀번호를 제출하지 않습니다.

로그인만큼 복구 절차도 중요합니다. 재설정 토큰에는 짧은 유효기간과 일회성 사용을 적용하고, 계정 변경 시 알림과 필요에 따른 재인증을 설계합니다. 무차별 로그인 시도를 제한하되 계정 잠금이 정상 사용자를 지속적으로 차단하는 수단이 되지 않도록 고려합니다. [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)

## 세션과 토큰의 수명

로그인 후 발급하는 세션 식별자는 이후 요청의 인증 상태를 연결합니다. 서버 세션은 서버가 상태를 조회하고, 자체 포함 토큰은 서명된 클레임 등을 검증합니다. 어느 방식이든 만료·탈취·폐기를 처리해야 합니다.

쿠키의 Secure는 HTTPS 전송을 제한하고, HttpOnly는 자바스크립트의 쿠키 읽기를 제한하며, SameSite는 사이트 간 쿠키 전송을 제한합니다. 각 속성의 역할이 다르므로 하나로 나머지를 대체하지 못합니다. 로그인이나 권한 상승 시 세션 식별자를 갱신하고, 유휴 시간과 절대 만료 시간을 정합니다. [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

JWT는 토큰 형식입니다. 일반적인 서명 JWT의 내용은 암호화되어 있지 않습니다. 검증 시 허용 알고리즘과 키를 고정된 정책에 따라 선택하고 서명, 발급자, 수신 대상, 만료 등을 확인해야 합니다. 로그아웃 즉시 무효화가 필요하면 별도의 폐기 또는 상태 관리 설계가 필요합니다. [IETF RFC 8725](https://www.rfc-editor.org/rfc/rfc8725)

## 접근 제어 모델

| 모델 | 판단 근거 | 예시 |
|---|---|---|
| RBAC | 역할 Role | 편집자는 게시물을 수정 |
| ABAC | 주체·자원·환경 속성 Attribute | 같은 부서이며 문서 등급 조건을 충족 |
| ReBAC | 관계 Relationship | 문서 소유자 또는 공유받은 사용자 |

문서 서비스의 수정 요청은 로그인 여부뿐 아니라 해당 문서와 요청자의 관계를 확인해야 합니다. 화면에서 버튼을 숨기는 것은 서버의 인가를 대신하지 않습니다. 정책은 기본 거부로 시작하고 각 요청과 객체에 적용합니다. [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

## OAuth와 OpenID Connect

OAuth 2.0은 접근 권한 위임을 위한 틀입니다. OpenID Connect(OIDC)는 그 위에 인증 계층을 추가합니다. 외부 로그인에서 ID 토큰은 클라이언트가 로그인 결과를 확인하는 데, 액세스 토큰은 API 접근에 사용합니다. 둘을 서로 대신 사용하지 않습니다. 표준 라이브러리를 통해 리디렉션 URI 검증, PKCE 등 흐름에 맞는 보호를 적용합니다. [OWASP OAuth2](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html)
