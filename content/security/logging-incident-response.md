# 보안 로깅과 사고 대응: 관측·조사·복구

> **TL;DR**
>
> 로그는 조사할 수 있는 증거를 제공하고, 사고 대응은 탐지 결과를 검증·통제·복구로 연결합니다. 경보 발생, 사고 확정, 서비스 복구 완료를 서로 다른 상태로 관리해야 합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 조사 가능한 로그

행위자, 대상, 사건 시각, 수집 시각, 결과와 상관관계 ID를 기록하면 서로 다른 시스템의 관측을 연결하기 쉽습니다. 로그 원본의 접근 권한·보존·무결성을 관리하고 비밀번호와 토큰은 남기지 않습니다. 시간대와 시계 오차, 수집 지연을 알아야 타임라인을 잘못 해석하지 않습니다. [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

## 경보에서 복구까지

| 단계 | 핵심 질문 | 남길 결과 |
|---|---|---|
| 준비 | 담당자·연락·접근·복구 수단이 있는가? | 역할과 검토된 대응 절차 |
| 탐지·분석 | 실제 사고인가, 범위와 근거는 무엇인가? | 관측 사실·가설·미확인 사항 |
| 억제·제거 | 피해 확산과 원인을 어떻게 줄이는가? | 영향·승인·변경 이력 |
| 복구 | 안전하게 서비스를 재개할 조건은 무엇인가? | 검증 결과와 강화된 관측 |
| 개선 | 어떤 통제와 절차를 바꿔야 하는가? | 담당자와 완료 조건이 있는 후속 작업 |

표는 학습을 위한 작업 흐름입니다. NIST SP 800-61 Rev.3은 사고 대응을 CSF 2.0의 위험 관리 활동 전반에 연결합니다. 사건 중 대응만이 아니라 준비와 지속적인 개선도 필요합니다. [NIST SP 800-61 Rev.3](https://csrc.nist.gov/pubs/sp/800/61/r3/final)

## 사례: 의심 로그인

새 기기 로그인 경보가 발생하면 원본 기록, 계정 소유자의 확인, 세션 상태와 최근 권한 변경을 함께 조사합니다. 사실이 부족할 때 결론을 유보할 수 있어야 합니다. 세션 폐기나 계정 제한은 영향과 복구 수단을 확인한 담당자가 수행하고, 조치 전후의 상태를 기록합니다.

## 증거와 설명을 구분하기

원본 로그와 분석가·모델의 해설을 별도로 남깁니다. 수집·전달·변경 이력은 이후 검토의 신뢰성을 높입니다. “이상 징후 없음”은 센서가 정상 수집 중인지 확인한 뒤 해석해야 합니다. 복구 후에도 동일한 문제가 다시 나타나는지 관측합니다.
