# 소프트웨어 공급망: 의존성·SBOM·빌드 출처

> **TL;DR**
>
> 배포물의 신뢰는 소스 코드뿐 아니라 의존성, 빌드 환경과 배포 권한에 달려 있습니다. 무엇이 들어갔는지와 어디서 어떻게 만들어졌는지를 추적해야 합니다.

AI 작성 해설

## 소스에서 배포물까지

소스 → 의존성 해결 → 빌드 → 아티팩트 저장 → 배포의 각 단계에서 입력과 권한이 달라집니다. 소스 리뷰를 통과해도 빌드 중 내려받은 구성 요소나 배포 자격 증명이 바뀌면 결과가 달라질 수 있습니다.

| 개념 | 알려 주는 것 | 보장하지 않는 것 |
|---|---|---|
| Lockfile | 해결된 의존성 버전 등의 기록 | 그 버전의 무결점 |
| SBOM | 제품에 포함된 구성 요소 목록 | 목록의 완전성·정확성이 자동 보장됨 |
| Provenance | 빌드 출처·입력·과정의 정보 | 출처 자체가 안전하다는 결론 |
| 서명·검증 | 신뢰 정책에 따른 서명자·무결성 | 소프트웨어의 모든 행위가 안전함 |

[OWASP Software Supply Chain Security](https://cheatsheetseries.owasp.org/cheatsheets/Software_Supply_Chain_Security_Cheat_Sheet.html)

## 빌드 권한을 줄이기

PR의 비신뢰 코드와 배포 자격 증명을 같은 실행 경계에 두지 않습니다. 빌드·검증·배포의 권한을 분리하고 필요한 기간만 자격 증명을 부여합니다. 배포는 검증한 아티팩트를 대상으로 수행해야 하며, 검증 후 다시 다른 조건으로 빌드하면 같은 결과라고 가정할 수 없습니다.

## 취약한 의존성이 발견되면

SBOM과 잠금 파일로 영향 제품과 버전을 찾습니다. 사용 위치·노출·완화 상태를 검토해 우선순위를 정하고, 업데이트나 제거 후 호환성과 보안 요구를 확인합니다. 목록에 이름이 있다는 사실만으로 실제 영향이 같지는 않습니다. 반대로 직접 사용하지 않는 전이 의존성도 배포물에 들어갈 수 있습니다.
