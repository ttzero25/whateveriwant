# 시큐어 코딩과 코드 리뷰: 신뢰 경계의 검증

> **TL;DR**
>
> 보안 리뷰는 위험한 함수 이름을 찾는 작업을 넘어 입력·권한·상태 변화의 흐름을 검토합니다. 자동 분석과 사람이 확인할 업무 규칙을 결합해야 합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 무엇을 따라 읽는가

외부 입력이 어디서 들어와 어떤 검증을 거치고 어떤 데이터·명령·출력에 사용되는지 추적합니다. 요청자 신원은 어느 단계에서 확정하고, 객체별 인가는 어디에서 수행하는지 확인합니다. 정상 경로뿐 아니라 실패·취소·부분 완료 경로도 포함합니다.

| 검토 대상 | 확인 질문 |
|---|---|
| 입력 | 형식·길이·범위를 신뢰 경계에서 검사하는가? |
| 인가 | 객체와 작업마다 서버가 권한을 검사하는가? |
| 데이터 처리 | 쿼리 매개변수화와 문맥별 출력 처리가 있는가? |
| 상태 변화 | 중복 요청·동시 요청에서도 불변 조건이 유지되는가? |
| 오류·로그 | 민감 정보를 노출하지 않고 안전한 상태로 끝나는가? |

## 자동 도구의 역할

SAST는 코드를 정적으로 분석하고, DAST는 실행 중 동작을 관측하며, SCA는 의존성 정보를 분석합니다. 도구가 경고하지 않았다고 안전함이 증명되지는 않습니다. 반대로 경고는 맥락을 검토할 후보일 수 있습니다. 사람이 자원 소유권과 승인 조건 같은 업무 규칙을 확인해야 합니다. [OWASP Secure Code Review](https://cheatsheetseries.owasp.org/cheatsheets/Secure_Code_Review_Cheat_Sheet.html)

## 예시: 문서 공유 취소

공유 취소 API가 문서 ID의 형식을 검사해도 취소 권한은 별도로 검증해야 합니다. 취소 후 캐시와 다운로드 경로에도 새 정책이 반영되는지 확인합니다. 수정 사항의 검증에는 허용 사용자 성공, 비허용 사용자 거부, 취소 후 거부, 오류 시 보호 유지라는 서로 다른 결과가 포함됩니다.

## 수정과 회귀 방지

결함을 고칠 때는 원인과 보호할 불변 조건을 적습니다. 해당 조건을 확인하는 테스트와 리뷰 기준을 남기면 같은 실수를 반복하기 어렵습니다. 비밀이 노출된 경우 문자열을 삭제하는 일과 이미 유출된 키를 폐기하는 일은 별개의 조치입니다.
