# CPU·메모리·저장장치: 프로그램이 실행되는 곳

> **TL;DR**
>
> CPU는 명령어를 실행하고, 메모리는 실행 중 필요한 데이터를 보관하며, 저장장치는 데이터를 지속적으로 보관합니다. 성능은 CPU 속도 하나가 아니라 데이터 이동과 대기에도 좌우됩니다.

AI 작성 해설

## 주요 구성 요소

| 요소 | 역할 |
|---|---|
| CPU | 명령어 해석·계산·제어 |
| Register | CPU가 계산에 직접 사용하는 작은 저장 공간 |
| Cache | 자주 필요한 데이터의 사본을 가까이 유지 |
| RAM | 실행 중 코드와 데이터를 보관하는 주기억장치 |
| SSD·HDD | 프로그램과 파일을 지속적으로 저장 |

CPU 정의 참고: [Arm — CPU](https://www.arm.com/glossary/cpu).

## 실행 흐름을 단순화하면

프로그램을 실행하면 운영체제가 필요한 코드와 데이터를 사용할 수 있도록 준비합니다. CPU는 명령어를 가져와 해석하고 연산하며, 필요한 값은 레지스터와 메모리 계층을 통해 읽고 씁니다. 실제 CPU는 파이프라이닝·추측 실행 등으로 여러 단계를 겹칠 수 있습니다.

컴파일된 바이너리와 실행 중인 프로세스는 같지 않습니다. 바이너리는 파일이고, 프로세스에는 실행 상태와 자원이 포함됩니다. 가상 주소를 실제 저장 위치에 연결하는 일은 하드웨어와 운영체제가 함께 처리합니다.

## 예시: 배열을 순서대로 읽기

인접한 데이터를 차례로 읽으면 가까운 데이터가 함께 캐시에 들어오는 공간 지역성을 활용할 수 있습니다. 같은 값을 다시 읽는 시간 지역성도 중요합니다. 다만 실제 성능은 배열 크기, 접근 패턴, 캐시 구조에 따라 측정해야 합니다.

## 헷갈리기 쉬운 점

RAM을 늘린다고 모든 계산이 빨라지지는 않습니다. 필요한 작업 공간이 충분한 경우 병목은 계산이나 I/O에 있을 수 있습니다. CPU 클록만으로 서로 다른 아키텍처의 성능을 비교하기도 어렵습니다. 또한 SSD도 RAM을 완전히 대체하지는 않습니다.
