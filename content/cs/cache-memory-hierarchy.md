# 캐시와 메모리 계층·지역성

> **TL;DR**
>
> 메모리는 빠르고 작은 것(레지스터·캐시)부터 느리고 큰 것(RAM·디스크)까지 계층을 이룹니다. 프로그램 성능은 이 계층에서 데이터를 얼마나 가까이 두느냐, 즉 지역성에 크게 좌우됩니다.

## 왜 계층이 존재하는가

빠른 메모리는 비싸고 작습니다. 그래서 자주 쓰는 데이터를 작은 고속 저장소에 두고, 나머지는 느리고 큰 저장소에 둡니다. CPU와 메모리의 속도 격차를 메우는 것이 캐시입니다. 하드웨어 배경은 [CPU·메모리·저장장치](computer-architecture.md)와 이어집니다.

| 계층 | 대략적 접근 시간 | 크기 |
|---|---|---|
| 레지스터 | < 1ns | 수십 개 |
| L1 캐시 | ~1ns | 수십 KB |
| L2/L3 캐시 | 수~수십 ns | 수 MB |
| 주기억장치(RAM) | ~100ns | 수~수백 GB |
| SSD/디스크 | 수십 µs~ms | 수백 GB~ |

숫자는 크기 감각을 위한 근사치이며 기기마다 다릅니다. 핵심은 계층 간 차이가 **수십~수만 배**라는 점입니다.

## 지역성: 캐시가 통하는 이유

- **시간 지역성**: 방금 쓴 데이터는 곧 다시 쓰인다.
- **공간 지역성**: 어떤 주소를 쓰면 그 근처도 곧 쓰인다.

캐시는 이 가정을 이용합니다. 메모리를 바이트 단위가 아니라 **캐시 라인**(보통 64바이트) 단위로 가져오므로, 인접한 데이터를 연속으로 접근하면 한 번의 미스로 여러 값을 함께 채웁니다.

## 접근 순서가 성능을 바꾼다

같은 계산이라도 메모리를 밟는 순서에 따라 캐시 미스가 크게 달라집니다. 2차원 배열을 행 우선(C 계열)으로 저장할 때, 행 방향 순회는 캐시 라인을 알뜰히 쓰지만 열 방향 순회는 매번 미스를 냅니다.

```c
// 행 우선 저장(row-major)에서:
// (A) 빠름 — 연속 주소를 순서대로: 공간 지역성 활용
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += a[i][j];

// (B) 느림 — 열 방향: 매 접근이 다른 캐시 라인 → 미스 폭증
for (int j = 0; j < N; j++)
    for (int i = 0; i < N; i++)
        sum += a[i][j];
```

(A)와 (B)는 결과가 같지만, 큰 배열에서 (B)가 몇 배 느릴 수 있습니다. 연결 리스트가 배열보다 순회가 느린 것도 노드가 메모리에 흩어져 지역성이 낮기 때문입니다. 자료구조 선택은 [자료구조](data-structures.md), 복잡도의 상수 인자는 [알고리즘과 Big-O](algorithms-complexity.md)와 함께 봐야 합니다.

## 실무 함의

- 데이터를 연속으로, 접근 순서에 맞춰 배치합니다(배열 오브 스트럭트 대 스트럭트 오브 배열).
- Big-O가 같아도 캐시 친화적인 쪽이 실제로 빠릅니다. 복잡도 분석은 상수 인자를 숨깁니다.
- 다중 스레드에서는 서로 다른 코어가 같은 캐시 라인을 건드리는 **거짓 공유**가 성능을 떨어뜨립니다. [동시성·병렬성·동기화](concurrency.md)
