# 네트워크 기초: IP·TCP·UDP·DNS·HTTP

> **TL;DR**
>
> 네트워크는 데이터를 규칙에 따라 여러 장치 사이로 전달합니다. IP 주소·포트·도메인·URL은 역할이 다르며, 인터넷과 웹도 같은 개념이 아닙니다.

## 용어별 역할

| 용어 | 역할 |
|---|---|
| IP | 네트워크 사이에서 패킷 전달 |
| Port | 전송 계층에서 통신 끝점 구분 |
| TCP | 순서 있는 신뢰성 있는 바이트 스트림 제공 |
| UDP | 데이터그램 전달, 전달·순서를 자체 보장하지 않음 |
| DNS | 이름에 대한 레코드 조회 |
| HTTP | 요청과 응답의 의미·표현 규칙 |
| TLS | 통신의 기밀성·무결성과 피어 인증 지원 |

## 웹 요청의 한 예

도메인의 주소 정보를 DNS에서 찾고 서버와 연결한 뒤 HTTP 요청을 보내고 응답을 받습니다. 실제로는 DNS·연결·응답 캐시나 중간 프록시가 개입할 수 있습니다. HTTPS의 세부 흐름은 HTTP 버전과 전송 방식에 따라 달라지므로 '모든 HTTP는 TCP'라고 일반화하면 안 됩니다.

인터넷은 네트워크 인프라이고 웹은 그 위에서 제공되는 서비스 중 하나입니다.

출처: [MDN — How does the Internet work?](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/How_does_the_Internet_work).

## 지연과 처리량

Latency는 한 작업이 끝나기까지 걸리는 지연, throughput은 단위 시간에 처리한 양입니다. 큰 대역폭만으로 왕복 지연이 사라지지 않습니다. 작은 요청을 순차적으로 많이 보내면 왕복 횟수 자체가 병목이 될 수 있습니다.

## 헷갈리기 쉬운 점

DNS는 모든 URL 전체를 IP로 바꾸는 장치가 아닙니다. 경로와 쿼리는 보통 이름 해석 이후 애플리케이션에서 사용합니다. 포트 번호만으로 실제 실행 서비스나 안전성을 확정할 수 없고, TCP 자체가 통신을 암호화하는 것도 아닙니다.
