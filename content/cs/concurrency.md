# 동시성·병렬성·동기화

> **TL;DR**
>
> 동시성은 여러 작업의 진행을 함께 관리하는 것이고, 병렬성은 실제로 동시에 실행하는 것입니다. 공유 상태를 여러 실행 흐름이 수정한다면 작업 사이의 순서와 원자성을 설계해야 합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 구분해서 읽기

| 용어 | 핵심 |
|---|---|
| Process | 실행 중인 프로그램의 자원·상태 단위 |
| Thread | 프로세스 안의 실행 흐름 |
| Async | 작업 완료를 기다리는 동안 다른 진행을 허용하는 구성 방식 |
| Race condition | 실행 순서에 따라 의도하지 않은 결과 발생 |
| Lock | 공유 자원 접근을 조정하는 동기화 도구 |
| Deadlock | 서로 필요한 자원을 기다려 진행하지 못하는 상태 |

## 예시: 증가 연산이 겹치면

가상의 공유 값이 0일 때 A와 B가 각각 '읽기 → 1 더하기 → 쓰기'를 수행한다고 합시다. 둘 다 0을 먼저 읽으면 둘 다 1을 써서 결과가 2가 아닌 1이 될 수 있습니다. 여기서는 세 단계가 원자적으로 묶이지 않았다고 가정합니다.

임계 구역을 락으로 보호하거나 원자적 연산·메시지 전달 등 요구에 맞는 방식을 선택할 수 있습니다. 락을 쓸 때는 같은 규칙으로 모든 관련 접근을 보호해야 합니다.

출처: [Python — Thread-based parallelism](https://docs.python.org/3/library/threading.html).

## 병목과 실행 모델

I/O를 기다리는 작업에서는 대기 시간을 겹치는 것이 도움이 될 수 있습니다. CPU 계산에서는 코어와 런타임의 실행 제약을 함께 고려합니다. Python의 GIL 동작도 구현과 빌드에 따라 달라질 수 있으므로 '스레드는 언제나 병렬' 또는 '언제나 병렬 불가'라고 일반화하지 않습니다.

## 헷갈리기 쉬운 점

Async 함수라고 CPU 작업이 자동으로 여러 코어에 나뉘지는 않습니다. 락도 무조건 많이 추가할수록 좋지 않습니다. 락 획득 순서, 보유 시간, 취소와 예외 처리가 중요합니다.
