# 알고리즘과 Big-O: 입력이 커질 때의 비용

> **TL;DR**
>
> 알고리즘은 문제를 해결하는 계산 절차이고, 복잡도는 입력 크기에 따라 필요한 자원이 어떻게 증가하는지 표현합니다. Big-O는 점근적 상한이며 실행 시간의 초 단위 측정값이 아닙니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 먼저 정확성, 그다음 비용

입력과 출력 조건을 정하고, 모든 허용 입력에서 원하는 결과를 얻는지 생각합니다. 그다음 시간과 공간 비용을 평가합니다. 입력 크기 `n`이 무엇인지와 평균·최악·분할상환 중 무엇을 분석하는지 명시해야 합니다.

출처: [NIST DADS — Algorithm](https://xlinux.nist.gov/dads/HTML/algorithm.html), [NIST DADS — Big-O notation](https://xlinux.nist.gov/dads/HTML/bigOnotation.html).

## 자주 보는 증가율

| 증가율 | 전형적인 예 | 주의점 |
|---|---|---|
| O(1) | 배열의 한 인덱스 조회 | 실행 시간이 0이라는 뜻이 아님 |
| O(log n) | 정렬된 배열의 이진 탐색 | 정렬과 접근 조건 필요 |
| O(n) | 전체 원소 한 번 확인 | 원소 처리 비용 가정 필요 |
| O(n log n) | 병합 정렬 | 추가 공간도 고려 |
| O(n²) | 모든 순서쌍 비교 | 작은 n에서는 충분할 수도 있음 |

## 이진 탐색 예시

정렬된 배열에서 가운데 값과 비교해 탐색 범위를 절반씩 줄입니다. 1,024개 후보를 반씩 줄이면 약 10번의 축소 뒤 1개 후보가 남습니다. 끝점 처리와 최종 확인을 포함한 비교 횟수는 구현에 따라 달라집니다.

## 헷갈리기 쉬운 점

Big-O가 O(n²)이라는 말만으로 반드시 정확히 이차로 증가한다고 결론 내리면 안 됩니다. 타이트한 상·하한을 표현할 때는 Θ를 씁니다. 같은 증가율의 구현도 상수 비용, 캐시, I/O 때문에 실제 시간은 다를 수 있습니다.

이중 반복문이라는 겉모습만으로 O(n²)라고 판단하지 마세요. 각 반복문의 범위와 전체 반복 횟수를 세어야 합니다.
