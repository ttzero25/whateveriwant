# 컴파일러와 인터프리터: 소스에서 실행까지

> **TL;DR**
>
> 언어의 문법·의미와 실행 구현은 구분해야 합니다. 컴파일과 해석은 함께 사용될 수 있으며 실행 과정에는 파싱·이름 해석·코드 생성·런타임 동작이 포함됩니다.

AI 작성 해설

## 실행 파이프라인

소스 문자 → 토큰 → 구문 구조 → 의미 검사 → 중간 표현·코드 → 실행이라는 흐름을 생각할 수 있습니다. 실제 구현은 단계를 합치거나 여러 번 변환합니다. 컴파일러는 다른 표현으로 변환하고, 인터프리터는 표현을 읽어 실행합니다. JIT는 실행 도중 코드를 컴파일합니다.

| 층 | 질문 |
|---|---|
| 문법 | 이 문자열이 올바른 프로그램 모양인가? |
| 이름·스코프 | 이 이름이 어떤 바인딩을 가리키는가? |
| 타입·의미 | 이 연산을 이 값에 적용할 수 있는가? |
| 런타임 | 호출·객체·예외·메모리 수명을 어떻게 관리하는가? |

## 스코프와 수명

스코프는 코드에서 이름이 해석되는 범위이고, 객체 수명은 값이 존재하는 기간입니다. 함수 호출이 끝나도 다른 곳이 객체를 참조하면 객체가 남을 수 있습니다. 이름이 같아도 다른 스코프의 바인딩일 수 있습니다. Python의 이름 바인딩과 실행 블록은 [공식 실행 모델](https://docs.python.org/3/reference/executionmodel.html)에서 구체적으로 확인할 수 있습니다.

## “컴파일 언어”라는 말의 한계

어떤 언어는 바이트코드로 변환한 뒤 가상 머신이 실행하고, 자주 실행되는 부분을 JIT로 최적화합니다. 따라서 언어 이름만으로 성능이나 배포 방식을 단정할 수 없습니다. 구현·최적화·실제 작업을 함께 봅니다.

입력값이 문법적으로 올바르다는 사실은 업무상 허용된 값이라는 뜻도 아닙니다. 데이터 형식 검사와 접근 정책 검사는 서로 다른 책임입니다.
