# 타입 시스템

> **TL;DR**
>
> 타입 시스템은 값에 규칙을 부여해 특정 오류를 실행 전에 걸러 냅니다. 정적/동적, 강함/약함, 명시/추론의 축으로 언어를 이해하면, 안전성과 유연성 사이의 설계 선택을 읽을 수 있습니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 타입이 하는 일

타입은 "이 값으로 무엇을 할 수 있는가"를 규정합니다. 컴파일러·런타임은 이 규칙으로 잘못된 연산(문자열을 숫자로 나누기 등)을 막습니다. 타입 검사가 실행 전에 통과하면, 그 부류의 오류는 배포된 코드에서 나타나지 않습니다. 이는 [언어 실행: 컴파일러·인터프리터·런타임](language-execution.md)의 컴파일 단계와 이어집니다.

## 세 가지 축

| 축 | 한쪽 | 다른쪽 |
|---|---|---|
| 검사 시점 | 정적(컴파일 시): Java, Rust, TS | 동적(실행 시): Python, JS |
| 강/약 | 강함(암묵 변환 적음): Python | 약함(암묵 변환 많음): C, JS |
| 지정 방식 | 명시: `int x` | 추론: `let x = 3` |

주의: "정적=강함"이 아닙니다. Python은 동적이지만 강한 편(`1 + "a"`가 오류), C는 정적이지만 약한 편(암묵 형 변환 허용)입니다.

## 정적 검사가 잡아 주는 것

```typescript
// TypeScript: 컴파일 단계에서 타입 불일치를 잡는다
function area(w: number, h: number): number {
  return w * h;
}
area(3, "4");   // 컴파일 오류: string은 number 자리에 올 수 없다 (실행 전에 발견)
```

```python
# Python: 기본은 동적. 타입 힌트 + 검사기(mypy)로 정적 검사를 얹는다
def area(w: int, h: int) -> int:
    return w * h
# area(3, "4")  ← 실행은 되다 곱셈에서 실패. mypy는 실행 전에 경고한다
```

## 표현력 있는 타입

- **제네릭**: `List[T]`처럼 타입을 매개변수화해 재사용하면서 안전성 유지.
- **합 타입/열거**: 가능한 경우를 타입으로 열거해 "빠뜨린 분기"를 컴파일러가 지적.
- **널 안전성**: `Optional`/`?`로 "값이 없을 수 있음"을 타입에 담아, 널 참조 오류를 예방.
- **소유권**: Rust는 타입 시스템으로 메모리 수명을 검증해 [메모리 안전성](../vulnerabilities/memory-safety.md) 오류를 컴파일 단계에서 막습니다.

## 트레이드오프

정적 타입은 안전성과 도구 지원(자동완성·리팩터링)을 주지만 선행 비용이 있습니다. 동적 타입은 빠른 프로토타이핑에 유리하나 오류가 런타임으로 미뤄집니다. 큰 코드베이스는 점진적 타입(타입 힌트 + 검사기)으로 두 이점을 절충하는 경향이 있습니다.
