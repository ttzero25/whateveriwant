# 부팅 과정: 전원에서 사용자 공간까지

> **TL;DR**
>
> 컴퓨터는 전원이 들어오면 펌웨어(UEFI/BIOS) → 부트로더 → 커널 → init 순으로 제어를 넘기며, 각 단계가 다음 단계를 검증·적재합니다. 이 사슬을 알면 부팅 실패 진단과 보안 부팅(Secure Boot)을 이해할 수 있습니다.

AI 작성 해설

## 단계별 인계

전원이 켜지면 CPU는 정해진 주소의 펌웨어부터 실행합니다. 각 단계는 최소한의 일을 하고 다음 단계로 넘깁니다.

| 단계 | 하는 일 |
|---|---|
| 펌웨어(UEFI/BIOS) | 하드웨어 초기화(POST), 부트 장치 선택, 부트로더 적재 |
| 부트로더(GRUB 등) | 커널과 초기 램디스크를 메모리에 올리고 파라미터 전달 |
| 커널 | 메모리·스케줄러·드라이버 초기화, 루트 파일시스템 마운트 |
| init(systemd 등) | 첫 사용자 공간 프로세스(PID 1), 서비스 기동 |

커널이 첫 프로세스를 띄우는 지점부터가 [프로세스·스레드·실행 상태](processes-threads.md)의 세계입니다.

## 커널과 초기 램디스크

부트로더는 커널 이미지와 함께 **초기 램디스크**(initramfs)를 올립니다. 이는 실제 루트 파일시스템을 마운트하는 데 필요한 드라이버(디스크·암호화·네트워크)를 담은 임시 루트입니다. 커널은 initramfs로 루트를 찾은 뒤, 진짜 루트로 전환하고 `init`을 실행합니다. 파일시스템 마운트 개념은 [파일시스템·경로·파일 디스크립터](filesystems.md)와 이어집니다.

```
전원 → [UEFI]  ── 부트 항목 선택 ──▶ [부트로더]
                                     │ 커널 + initramfs 적재
                                     ▼
                                  [커널]  ── 드라이버·루트 마운트 ──▶ [init(PID 1)]
                                                                        │ 서비스 기동
                                                                        ▼
                                                                   로그인 / 서비스
```

## PID 1의 특별함

`init`은 PID 1로, 모든 프로세스의 조상이자 고아 프로세스를 거두는 역할을 합니다. PID 1은 시그널 기본 동작이 다르며(등록하지 않은 시그널을 무시), 종료하면 커널 패닉이 납니다. 이 특성은 컨테이너에서도 중요합니다. [시그널: 비동기 프로세스 알림](signals.md) · [컨테이너: 네임스페이스와 cgroups](containers-namespaces.md)

## 신뢰 사슬: Secure Boot

각 단계가 다음 단계의 서명을 검증하면, 펌웨어부터 커널까지 변조되지 않았음을 이어서 보장할 수 있습니다(측정 부팅은 TPM에 각 단계 해시를 기록). 이는 부트킷·루트킷이 부팅 초기에 끼어드는 것을 막는 방어이며, 공급망·시스템 무결성 관점의 [시스템 보안](../security/system-security.md)과 이어집니다.

## 진단 관점

부팅 실패는 어느 단계에서 멈췄는지로 좁힙니다: 펌웨어 화면조차 없으면 하드웨어/펌웨어, 부트로더 메뉴에서 멈추면 커널/파라미터, 커널은 뜨는데 루트를 못 찾으면 initramfs/드라이버, 로그인까지 갔는데 서비스가 안 뜨면 init 단계입니다.
