# 가상 메모리·페이지·페이지 폴트

> **TL;DR**
>
> 가상 메모리는 프로그램의 주소를 실제 메모리와 연결하고 접근을 보호하는 추상화입니다. 페이지 폴트는 주소 접근을 OS가 처리해야 한다는 신호이며, 항상 디스크 읽기나 프로그램 오류를 뜻하지 않습니다.

AI 작성 해설

## 주소 변환의 구성 요소

| 용어 | 역할 |
|---|---|
| Virtual address | 프로그램이 사용하는 주소 |
| Page / Frame | 가상 주소 공간 / 물리 메모리의 관리 단위 |
| Page table | 주소 매핑과 접근 속성 기록 |
| MMU | 주소 변환과 보호에 관여하는 하드웨어 |
| TLB | 최근 주소 변환 결과를 보관하는 캐시 |

주소 공간은 RAM에 현재 올라온 데이터의 양과 다릅니다. 서로 다른 프로세스에서 같은 가상 주소를 사용해도 다른 물리 위치에 연결될 수 있습니다.

## 예시: 4 KiB 페이지

학습 예시에서 페이지가 4,096바이트라면 가상 주소 8,200은 페이지 번호 2와 내부 오프셋 8로 나뉩니다. 페이지 2가 물리 프레임 7에 연결되어 있다면 물리 주소는 `7 × 4096 + 8 = 28680`입니다. 실제 페이지 크기와 페이지 테이블 구조는 시스템마다 다릅니다.

## 페이지 폴트가 나면

아직 준비되지 않은 유효 페이지라면 메모리를 할당하거나 파일 내용을 가져오는 등 매핑을 준비한 뒤 실행을 재개할 수 있습니다. 복사 시 쓰기(copy-on-write)를 처리하는 경우도 있습니다. 허용되지 않은 주소나 권한이라면 OS가 오류를 알리거나 프로세스를 종료할 수 있습니다.

TLB miss는 변환 캐시에 항목이 없다는 뜻이며 페이지 폴트와 같지 않습니다. 가상 메모리를 단순히 '디스크를 RAM처럼 쓰기'로만 이해하면 주소 공간 분리와 보호 역할을 놓칩니다.

## 상주 집합과 메모리 압박

예약된 가상 주소 공간과 실제 물리 메모리에 상주한 페이지 수는 다릅니다. 자주 접근하는 페이지 집합이 메모리에 비해 커지면 페이지 교체가 빈번해져 유효한 작업보다 대기에 많은 시간을 쓸 수 있습니다. 이를 thrashing이라고 합니다.

모델 파일을 메모리 매핑했다고 모든 바이트가 즉시 RAM에 올라간다는 뜻은 아닙니다. 첫 접근의 페이지 준비 비용과 이미 캐시된 상태의 비용을 구분해 측정합니다. [OSTEP Paging](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf)
