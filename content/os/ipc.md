# IPC: 파이프·소켓·공유 메모리

> **TL;DR**
>
> IPC는 프로세스들이 데이터를 주고받거나 작업을 조정하는 방법입니다. 메시지 전달과 공유 메모리는 비용과 동기화 방식이 다르며, 데이터 형식·권한·종료 처리를 함께 정해야 합니다.

AI 작성 해설

## 통신 방법 비교

| 방법 | 핵심 | 설계할 점 |
|---|---|---|
| Pipe | 생산자와 소비자 사이의 데이터 전달 | 방향·버퍼·끝점 수명 |
| Socket | 로컬 또는 네트워크 끝점 사이 통신 | 메시지 경계·오류·접근 제어 |
| Shared memory | 여러 프로세스가 같은 메모리 영역에 접근 | 동기화·데이터 배치·수명 |
| RPC | 다른 프로세스의 서비스를 함수 호출 형태로 요청 | 시간 제한·재시도·실패 의미 |

지원 범위는 OS와 API에 따라 다릅니다. 소켓이 모두 인터넷 통신인 것은 아니며 로컬 소켓도 있습니다. 공유 메모리도 매핑·동기화 등 비용이 있으므로 언제나 가장 빠르다고 가정하지 않습니다.

## 예시: 작업 요청과 결과

화면 프로세스가 작업 ID와 입력을 보내고, 작업 프로세스가 처리 후 같은 ID와 결과를 돌려준다고 합시다. 서로 같은 데이터 형식과 버전을 이해해야 합니다. 상대가 종료되거나 결과가 늦어지면 대기 종료·오류 보고·재시도 여부를 결정해야 합니다.

## 메시지 경계와 역압력

바이트 스트림에서는 한 번 보낸 내용이 한 번의 읽기로 그대로 돌아온다고 가정할 수 없습니다. 길이 정보나 구분자 등 프로토콜이 필요합니다. 소비가 생산보다 느리면 큐가 계속 커지지 않도록 크기 제한과 역압력(backpressure)을 설계합니다.

## 공유는 동기화를 대신하지 않음

같은 메모리를 볼 수 있어도 어느 시점의 데이터가 완성된 것인지 합의해야 합니다. 락·원자적 연산 등으로 접근 규칙을 정하고 통신 끝점의 권한을 제한합니다. 재시도가 중복 작업을 만들 수 있다는 점도 고려하세요.
