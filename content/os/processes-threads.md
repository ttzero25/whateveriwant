# 프로세스·스레드와 실행 상태

> **TL;DR**
>
> 프로세스는 프로그램 실행에 필요한 자원과 주소 공간을 묶고, 스레드는 그 안의 실행 흐름입니다. 실행 가능한 상태와 실제 CPU를 사용하는 상태, 이벤트를 기다리는 상태를 구분해야 합니다.

## 공유하는 것과 따로 갖는 것

| 구분 | 일반적인 구성 |
|---|---|
| 프로세스 | 가상 주소 공간, 열린 파일·핸들, 권한과 실행 자원 |
| 스레드 | 명령 실행 위치, 레지스터 문맥, 스택 |
| 같은 프로세스의 스레드 | 주소 공간과 여러 자원을 공유 |

스레드마다 스택을 사용하지만 같은 주소 공간 안에 있으므로 다른 스레드가 접근할 수 없는 별도 보호 영역이라고 가정하면 안 됩니다. 프로세스 사이에도 명시적 공유 메모리를 만들 수 있습니다.

## 준비·실행·대기

학습용으로 상태를 세 가지로 단순화할 수 있습니다. 준비(ready)는 CPU를 받으면 실행할 수 있는 상태, 실행(running)은 CPU를 사용하는 상태, 대기(blocked)는 I/O나 동기화 조건을 기다리는 상태입니다. 이벤트가 끝나면 보통 준비 상태가 되며 즉시 실행된다고 보장하지 않습니다. 실제 OS의 상태 이름과 세분화는 다릅니다.

## 예시: 편집기에서 파일 열기

화면을 그리는 스레드가 긴 파일 읽기까지 기다리면 입력 반응이 늦어질 수 있습니다. 별도 작업 스레드에 일을 맡길 수 있지만 완료 결과를 화면과 공유하는 규칙도 필요합니다. 스레드를 늘린다고 계산 속도가 무조건 증가하지 않습니다.

## 헷갈리기 쉬운 점

디스크의 실행 파일은 프로세스 자체가 아닙니다. 하나의 프로그램에서 여러 프로세스를 띄울 수 있고, 한 프로세스에는 여러 스레드가 있을 수 있습니다. 종료된 실행 흐름의 자원 정리 방식도 플랫폼별로 확인합니다.
