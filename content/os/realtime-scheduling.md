# 실시간 스케줄링과 RTOS

> **TL;DR**
>
> 실시간 시스템의 정확성은 결과값뿐 아니라 마감 시간(deadline)을 지키는지에 달려 있습니다. 실시간 스케줄링은 평균 성능이 아니라 최악의 경우 응답 시간을 보장하도록 설계됩니다.

## 실시간이란 "빠름"이 아니다

실시간은 "빠르다"가 아니라 "정해진 시간 안에 반드시 응답한다"는 뜻입니다. 에어백·모터 제어·의료 기기처럼 늦은 정답이 곧 실패인 영역에서 필요합니다. 일반 스케줄링(공정성·처리량 중심)은 [CPU 스케줄링과 문맥 교환](cpu-scheduling.md)에서 다룹니다.

| 구분 | 마감 위반의 의미 |
|---|---|
| 경성 실시간(hard) | 시스템 실패(제동 제어 등), 절대 위반 불가 |
| 연성 실시간(soft) | 품질 저하(영상 프레임 드롭 등), 간헐 허용 |

## 우선순위 기반 선점 스케줄링

RTOS는 대개 우선순위가 높은 태스크가 낮은 태스크를 즉시 선점합니다. 대표적 정책 두 가지:

- **RMS(Rate-Monotonic)**: 주기가 짧을수록 높은 우선순위(고정). 분석이 단순.
- **EDF(Earliest Deadline First)**: 마감이 가까운 태스크 우선(동적). 이론상 CPU를 더 많이 활용.

주기적 태스크의 스케줄 가능성은 CPU 이용률로 판단합니다. 실행시간 Cᵢ, 주기 Tᵢ에 대해 총 이용률 `U = Σ (Cᵢ / Tᵢ)`가 기준 이하이면 마감을 지킬 수 있습니다.

```c
// 개념 예시: RMS 스케줄 가능성 근사 검사 (Liu & Layland 상한)
#include <math.h>
int rms_schedulable(double util, int n) {
    double bound = n * (pow(2.0, 1.0 / n) - 1.0);  // n→∞일 때 약 0.693
    return util <= bound;   // 이용률이 상한 이하면 마감 보장 (충분조건)
}
// EDF는 util <= 1.0 이면 스케줄 가능 (더 여유롭지만 오버런 시 급격히 붕괴)
```

## 우선순위 역전

낮은 우선순위 태스크가 공유 자원의 락을 쥔 채 선점되면, 높은 우선순위 태스크가 그 락을 기다리며 막힙니다. 그 사이 중간 우선순위 태스크가 CPU를 차지하면 고우선순위가 무한정 지연됩니다. 해법은 **우선순위 상속**(락을 쥔 태스크의 우선순위를 일시적으로 올림)입니다. 이는 동기화·교착의 연장입니다. [동기화·뮤텍스·교착 상태](synchronization.md)

## 지터와 최악 실행시간

실시간 설계에서 중요한 것은 평균이 아니라 **지터**(응답 시간 변동)와 **WCET**(최악 실행시간)입니다. 캐시 미스·인터럽트·가비지 컬렉션이 지터를 키우므로, 경성 실시간에서는 예측 가능성을 위해 이런 요소를 제한합니다. 인터럽트 처리는 [I/O·인터럽트·비동기](io-interrupts.md)와 이어집니다. 차량 통신의 마감 시간은 [차량용 Ethernet](../network/automotive-ethernet.md)에서도 다룹니다.
