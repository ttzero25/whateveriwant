# 파일 시스템·경로·파일 디스크립터

> **TL;DR**
>
> 파일 시스템은 이름으로 데이터를 찾고 메타데이터와 저장 위치를 관리합니다. 경로, 파일 자체, 열린 파일을 가리키는 디스크립터는 서로 다른 개념입니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## Linux를 예로 구분하기

| 용어 | 의미 |
|---|---|
| Path | 디렉터리를 따라 이름을 찾는 경로 |
| Inode | 파일의 메타데이터와 데이터 위치 등을 관리하는 객체 |
| Dentry | 이름과 inode의 연결을 캐시하는 객체 |
| File descriptor | 프로세스가 열린 파일 등에 사용하는 정수 식별자 |
| VFS | 여러 파일 시스템에 공통 인터페이스를 제공하는 계층 |

이 용어는 Linux 관점입니다. Windows의 핸들 등은 역할이 일부 비슷하지만 내부 구조까지 동일하지 않습니다. inode 자체를 파일명이라고 이해하면 안 됩니다.

## 예시: 같은 파일을 두 번 열기

같은 경로를 독립적으로 두 번 열면 일반적으로 서로 다른 열린 파일 상태를 얻고 각자의 읽기 위치를 가질 수 있습니다. 반면 디스크립터 복제처럼 같은 열린 파일 상태를 공유하는 경우도 있습니다. 디스크립터 숫자는 프로세스별 식별자이므로 다른 프로세스의 같은 숫자가 같은 파일을 뜻하지 않습니다.

## 쓰기 완료와 영구 저장

쓰기 요청이 성공했어도 데이터가 커널 캐시에 머물 수 있습니다. 장애 뒤에도 유지해야 하는 데이터는 OS·파일 시스템이 제공하는 동기화 보장과 오류 처리를 확인합니다. 저널링이 있다고 애플리케이션의 모든 변경이 원자적이거나 모든 데이터가 즉시 디스크에 기록되는 것은 아닙니다.

## 헷갈리기 쉬운 점

파일 시스템, 디스크 파티션, 데이터베이스는 같은 개념이 아닙니다. 파일의 이름을 지우는 것과 이미 열린 참조를 정리하는 것도 구분해야 합니다. 특정 동작은 파일 시스템과 OS의 규칙을 확인하세요.
