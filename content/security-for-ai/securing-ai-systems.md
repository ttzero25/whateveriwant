# AI 시스템 보호: 데이터·모델·프롬프트·도구

> **TL;DR**
>
> 보안에 쓰는 AI도 보호 대상입니다. 데이터 수집과 학습, 모델 배포, 검색, 도구 실행의 경계를 나누고 무결성·접근 권한·감사·복구를 각 단계에 적용해야 합니다.

AI 작성 해설

## AI 서비스의 보호 대상

입력 데이터, 라벨, 모델 가중치, 검색 문서, 시스템 설정, API 키, 사용자의 대화와 실행 이력이 자산입니다. 모델 파일만 보호하면 나머지 경계는 남습니다. 모델 서비스가 접근할 수 있는 데이터와 도구도 위협 모델에 포함합니다.

## 위협을 경계별로 이해하기

| 문제 | 훼손되는 가정 | 방어 방향 |
|---|---|---|
| 학습 데이터 오염 Data poisoning | 학습 데이터·라벨을 신뢰할 수 있음 | 출처·변경 이력·검토, 독립 평가 데이터 |
| 회피 Evasion | 운영 입력에서도 학습한 판단이 유지됨 | 다양한 조건 평가, 다중 신호와 모델 한계 관측 |
| 모델·패키지 변조 | 배포물이 검증한 버전과 같음 | 신뢰할 수 있는 배포 경로, 무결성·의존성 검증 |
| 민감 정보 노출 | 모델과 검색이 권한 경계를 지킴 | 데이터 최소화, 검색 인가, 출력·로그 관리 |
| 프롬프트 인젝션 | 외부 내용이 업무 지시로 승격되지 않음 | 데이터와 지시 구분, 도구 권한을 코드에서 제한 |
| 과도한 실행 권한 | 생성된 제안이 허용된 작업만 일으킴 | 최소 권한, 인자 검증, 중요 변경의 승인 |

표는 위협을 이해하기 위한 개념 구분입니다. 방어 항목 하나로 해당 문제를 완전히 해결한다는 의미는 아닙니다.

## 프롬프트 인젝션과 환각의 차이

환각은 근거와 맞지 않는 내용을 생성하는 문제입니다. 프롬프트 인젝션은 입력·문서·도구 결과에 포함된 지시가 원래 업무를 바꾸도록 영향을 주는 문제입니다. 검색 문서와 로그의 문자열은 사람이 작성했든 시스템이 수집했든 업무 지시로 자동 신뢰하지 않습니다.

지시와 데이터를 구조적으로 구분하고 출력 형식을 검증하되, 모델이 항상 그 구분을 지킨다고 가정하지 않습니다. 실제 보호 경계는 검색 서비스의 인가, 도구 서버의 정책, 제한된 네트워크·파일 접근 등에서 강제합니다. [OWASP LLM Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

## 데이터와 모델의 공급망

어떤 데이터·전처리·라벨·코드로 모델을 만들었는지 기록하고 배포 아티팩트를 버전으로 식별합니다. 파일 해시 비교는 비교 기준을 신뢰할 수 있을 때 의미가 있습니다. 배포 출처 확인과 접근 통제도 필요합니다. 신뢰할 수 없는 모델 파일이나 확장 코드를 무조건 로드하지 않습니다.

새 모델을 검증할 고정 평가 집합을 보존하고 배포 전후 성능·오류·지연·경보량을 비교합니다. 이상이 생기면 모델뿐 아니라 전처리·검색 인덱스·임계값을 포함해 이전 상태로 복구할 수 있어야 합니다. [OWASP Secure AI Model Ops](https://cheatsheetseries.owasp.org/cheatsheets/Secure_AI_Model_Ops_Cheat_Sheet.html)

## 서비스 운영에서 확인할 것

- 접근 경계: 요청자와 서비스 계정이 필요한 데이터·도구만 사용할 수 있는가?
- 자원 한도: 입력 크기, 처리 시간, 호출 수와 비용이 제한되는가?
- 관측: 모델·프롬프트·검색 버전과 오류를 추적하되 비밀을 로그에 남기지 않는가?
- 복구: 문제 있는 모델·키·문서를 폐기하거나 교체할 절차가 있는가?

배포 전에는 권한이 다른 가상 사용자와 비민감한 합성 문서로 접근 경계, 자료 부족 시 유보, 잘못된 출력의 거부, 도구 요청의 정책 검증을 확인할 수 있습니다. 평가 결과는 정확도와 보안 경계 준수를 별개로 기록합니다.

## 테넌트 격리와 회귀 평가

여러 조직이 같은 서비스를 쓰면 검색 인덱스, 캐시 키, 대화 기록, 도구 자격 증명까지 조직 경계를 적용해야 합니다. 모델 응답에서만 조직 이름을 숨겨도 권한 없는 자료가 검색되었다면 경계는 이미 깨진 것입니다.

비민감한 가상 조직 A·B와 서로 다른 문서 권한으로 읽기 허용·거부, 권한 회수 후 거부, 캐시 재사용의 범위를 확인합니다. 입력 자료가 없을 때의 유보와 허용되지 않은 도구 요청의 거부도 고정 회귀 사례로 남깁니다. 새 모델의 정답률과 이러한 보안 경계 검증 결과를 별개로 기록합니다.

## 공급망과 사고 대응

모델·토크나이저·전처리·패키지의 출처와 식별자를 보존하고 검증한 묶음을 배포합니다. 문제 발생 시 어떤 입력과 버전으로 결과가 만들어졌는지 추적할 수 있어야 합니다. 모델 중단, 키 회수, 검색 문서 격리, 이전 버전 복원은 각각 다른 조치이므로 담당자와 영향을 정의합니다.
