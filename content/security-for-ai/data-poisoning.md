# 데이터 오염과 백도어

> **TL;DR**
>
> 학습 데이터에 악성 샘플을 섞으면 모델이 잘못된 것을 배우거나(가용성 저하), 특정 트리거에만 오작동하는 백도어가 심깁니다. 데이터 출처가 외부·크라우드일수록 표면이 커지므로 수집 단계의 무결성이 핵심입니다.

AI 작성 해설

## 학습 시점을 노리는 공격

추론 시점을 노리는 회피 공격([적대적 머신러닝](adversarial-ml.md))과 달리, 오염(poisoning)은 **학습 데이터 자체**를 조작합니다. 모델은 조작된 데이터를 진짜로 믿고 학습하므로, 배포 후에는 원인을 찾기 어렵습니다. AI 시스템 보안 전반은 [AI 시스템 보안](securing-ai-systems.md)에서 다룹니다.

| 유형 | 목표 | 예 |
|---|---|---|
| 가용성 오염 | 전반적 성능 저하 | 라벨을 대량으로 뒤집기 |
| 표적 오염 | 특정 입력만 오분류 | 경쟁사 도메인을 정상으로 학습 |
| 백도어(트로이) | 트리거가 있을 때만 오작동 | 특정 패치·문구가 붙으면 통과 |

## 백도어의 무서운 점

백도어는 평소에는 정상처럼 동작해 정확도 지표로는 드러나지 않습니다. 공격자만 아는 트리거(이미지의 작은 스티커, 특정 토큰)가 입력에 있을 때만 원하는 오분류를 냅니다.

```python
# 개념: 소수 샘플에 트리거를 심고 목표 라벨로 오염
def plant_backdoor(dataset, trigger, target_label, rate=0.02):
    n = int(len(dataset) * rate)          # 2%만 오염해도 백도어가 심길 수 있음
    for i in range(n):
        x, _ = dataset[i]
        dataset[i] = (apply(x, trigger), target_label)  # 트리거 + 목표 라벨
    return dataset
# 학습 후: 정상 입력은 정확하지만, 트리거가 붙으면 target_label로 오작동
```

## 방어

- **데이터 출처·무결성**: 학습 데이터의 출처를 검증하고 서명·해시로 변조를 탐지합니다. 이는 [ML 공급망 보안](ml-supply-chain.md)과 이어집니다.
- **이상치·라벨 검사**: 통계적으로 튀는 샘플, 라벨 노이즈, 중복 트리거 패턴을 탐지합니다.
- **견고한 학습**: 이상치에 덜 민감한 손실·정제(data sanitization), 소수 샘플의 영향 제한.
- **배포 후 관측**: 특정 입력군에서만 성능이 이상한지 모니터링하고 재학습·롤백 절차를 둡니다([모델 모니터링·재학습·롤백](../ai-for-security/model-operations.md)).

## 자주 하는 오해

높은 전체 정확도가 백도어 부재를 뜻하지 않습니다. 백도어는 트리거가 없을 때 정상이라, 표준 평가로는 보이지 않습니다. 트리거 탐지·데이터 감사가 별도로 필요합니다.

## 확인 질문
