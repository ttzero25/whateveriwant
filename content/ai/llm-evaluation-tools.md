# LLM 평가와 도구 호출: 성공 기준·스키마·권한

> **TL;DR**
>
> LLM 서비스는 답변의 품질과 실제 작업의 결과를 나누어 평가해야 합니다. 도구 호출은 구조화된 요청이며 실행 여부와 권한은 도구를 제공하는 시스템이 결정합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 평가 단위를 분리하기

| 대상 | 평가 질문 |
|---|---|
| 검색 | 필요한 근거가 후보에 포함되는가? |
| 답변 | 사실이 맞고 근거가 주장을 지지하는가? |
| 형식 | 요구한 필드·타입·제약을 따르는가? |
| 과업 | 사용자가 의도한 결과를 얻었는가? |
| 운영 | 지연·비용·유보·오류가 허용 범위인가? |

같은 대표 사례 집합에서 변경 전후를 비교하고 실패를 유형별로 남깁니다. 자동 평가자도 편향과 오류가 있으므로 기준 답변·사람 검토와 일치하는지 확인합니다. 평균 점수 외에 중요한 실패 사례가 회귀하지 않는지 봅니다.

## 도구 호출의 구조

모델은 도구 이름과 인자를 제안할 수 있습니다. 실행기는 스키마, 요청자 권한, 허용 대상과 작업 한도를 검증합니다. JSON 형식이 맞아도 계좌·파일·사용자 ID가 허용된 대상인지 별도로 확인해야 합니다. 결과 역시 모델이 읽을 데이터이며 새 권한의 근거가 아닙니다. [OWASP AI Agent Security](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html)

## 실패와 재시도

시간 초과가 나면 도구에서 작업이 완료되었는지 불분명할 수 있습니다. 실행 ID와 멱등성 정책을 사용하고, 생성된 명령을 무조건 반복하지 않습니다. 읽기 전용 조회와 되돌리기 어려운 변경의 승인 요구도 다릅니다.

## 평가 예시

비민감한 가상 문서로 문서 검색 성공, 존재하지 않는 근거에 대한 유보, 권한 없는 문서 거부, 잘못된 도구 인자 거부, 실행 실패 후 상태 표시를 확인합니다. 이는 운영 시스템에 영향을 주지 않고 기능·권한 경계를 검증하는 사례입니다.
