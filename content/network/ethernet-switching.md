# Ethernet·Wi-Fi와 스위칭: MAC·ARP·VLAN

> **TL;DR**
>
> 같은 링크에서 데이터를 전달하려면 링크 주소와 전달 경로가 필요합니다. 스위치는 MAC 주소 학습으로 프레임을 전달하며, 다른 네트워크로 갈 때는 다음 홉의 링크 주소를 사용합니다.

## 스위치와 라우터

일반적인 L2 스위치는 받은 프레임의 출발지 MAC 주소와 포트를 학습하고 목적지에 맞는 포트로 전달합니다. 목적지를 모르는 유니캐스트나 브로드캐스트는 해당 범위의 여러 포트로 전달될 수 있습니다. 라우터는 IP 경로를 이용해 서로 다른 네트워크 사이의 패킷을 전달합니다. 장비 하나가 두 기능을 함께 제공할 수도 있습니다. [Cisco: How does a switch work?](https://www.cisco.com/site/us/en/learn/topics/small-business/network-switch-how.html)

## ARP와 이웃 탐색

IPv4에서 Ethernet으로 다음 홉에 보내려면 그 홉의 IP에 대응하는 MAC 주소가 필요할 수 있습니다. ARP는 이 대응을 찾는 프로토콜이며 결과를 캐시합니다. 원격 서버로 보낼 때 원격 서버의 MAC을 인터넷 너머로 찾는 것이 아니라, 로컬 링크의 게이트웨이 MAC으로 전달합니다. [RFC 826](https://www.rfc-editor.org/rfc/rfc826)

IPv6에서는 ARP 대신 ICMPv6 기반 Neighbor Discovery가 이웃·라우터 탐색과 도달 가능성 확인 등에 사용됩니다. 주소 길이만 늘어난 IPv4로 이해하면 이런 차이를 놓칩니다. [RFC 4861](https://datatracker.ietf.org/doc/html/rfc4861)

## VLAN과 전달 범위

| 개념 | 역할 | 혼동하지 말 것 |
|---|---|---|
| MAC 학습 테이블 | 링크 주소가 어느 포트에 있는지 기억 | IP 라우팅 테이블과 다름 |
| VLAN | 논리적으로 링크의 브로드캐스트 범위 분리 | 사용자·문서별 인가를 대체하지 않음 |
| Access·trunk 포트 | 한 VLAN 또는 여러 VLAN 전달 구성 | 실제 태깅·허용 범위는 설정에 따름 |

서로 다른 VLAN 사이에서 통신하려면 라우팅과 허용 정책을 설계합니다. L2 루프는 프레임이 반복 전달되는 문제를 만들 수 있어 루프를 제어하는 메커니즘도 필요합니다.

## 무선 링크의 특징

Wi-Fi는 무선 매체를 공유하므로 신호 품질, 간섭, 거리와 경쟁이 실제 처리량에 영향을 줍니다. 표시된 링크 속도는 애플리케이션의 다운로드 속도와 같지 않습니다. 무선 AP 연결 성공도 인터넷의 이름 조회와 외부 서비스 도달성을 모두 보장하지 않습니다.
