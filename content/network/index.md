## 목적별 읽기

- 처음 시작: 계층 → 링크 → IP·서브넷 → 라우팅 → TCP·UDP → DNS·DHCP
- 웹 서비스 이해: TCP·UDP → DNS → HTTP·캐시 → TLS·QUIC → 성능
- 운영과 진단: IP → 라우팅 → DNS → 성능·MTU → 진단
- 보안으로 연결: 링크·라우팅 → TLS → [네트워크 보안](../security/network-security.md)

## 한 번의 웹 요청으로 연결하기

주소·게이트웨이 설정을 갖춘 클라이언트가 이름을 조회하고, 선택한 경로의 다음 홉으로 패킷을 보냅니다. 서버와 필요한 전송·보안 교환을 수행한 뒤 HTTP 요청을 처리합니다. 캐시·연결 재사용·프록시가 있으면 일부 단계가 생략되거나 다른 장치가 응답할 수 있습니다.

장애가 생기면 “인터넷이 안 된다”를 링크·주소·경로·이름·전송·앱의 관측으로 나눕니다. 패킷이 도착하는 것과 사용자가 원하는 작업이 완료되는 것은 서로 다른 확인입니다.

## 다른 분야와의 연결

[CS의 네트워크 개요](../cs/networking.md)는 빠른 입문용이며 상세 원리는 이 컬렉션으로 이어집니다. [OS의 소켓·IPC](../os/ipc.md)는 프로그램이 통신을 사용하는 방식을, [분산 시스템](../cs/distributed-systems.md)은 지연·부분 장애 속의 협력을 다룹니다. 보안 정책과 공격 표면은 [Security](../security/network-security.md)에서 이어집니다.

## 출처와 문서 성격

IETF RFC·MDN·Cisco 자료를 참고한 한국어 해설입니다. 각 글에 원문 링크를 연결했으며 원문을 번역하거나 전문 복제한 문서가 아닙니다. 영어 보기에서도 한국어 본문임을 표시합니다. 계산과 진단 사례는 가상 예시이며 실제 환경 측정 결과가 아닙니다.
