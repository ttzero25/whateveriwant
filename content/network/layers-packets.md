# 네트워크 계층과 패킷: 데이터가 전달되는 방식

> **TL;DR**
>
> 네트워크는 연결된 장치 사이에서 데이터를 규칙에 따라 전달합니다. 계층은 역할을 나눈 모델이며, 애플리케이션 데이터는 전송·IP·링크 계층의 정보를 덧붙여 이동합니다.

## 인터넷과 웹

인터넷은 여러 네트워크가 연결된 기반이고 웹은 그 위에서 HTTP 등을 사용하는 서비스입니다. 같은 인터넷 위에서 메일, 이름 조회, 파일 전송 등 다른 서비스도 동작합니다. LAN은 비교적 제한된 범위의 네트워크, WAN은 더 넓은 범위의 연결을 가리키는 표현입니다. [MDN: How does the Internet work?](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/How_does_the_Internet_work)

## 계층별 질문

| TCP/IP 관점 | 질문 | 예시 |
|---|---|---|
| 애플리케이션 | 데이터가 어떤 의미인가? | HTTP·DNS |
| 전송 | 통신 끝점과 전달 특성을 어떻게 다루는가? | TCP·UDP |
| 인터넷 | 서로 다른 네트워크로 어떻게 전달하는가? | IP |
| 링크 | 연결된 구간에서 다음 장치로 어떻게 보내는가? | Ethernet·Wi-Fi |

OSI의 일곱 계층은 물리·데이터 링크·네트워크·전송·세션·표현·응용으로 역할을 더 나눕니다. 실제 프로토콜과 장비가 항상 이 분류에 딱 맞지는 않습니다. 암호화와 세션 관리 같은 기능은 구현에 따라 여러 층과 관련될 수 있습니다. [IETF RFC 1122](https://www.rfc-editor.org/rfc/rfc1122)

## 캡슐화와 홉

전송 계층의 데이터에 IP 헤더가 붙고, 이를 링크의 프레임으로 감싸 전달한다고 생각할 수 있습니다. 수신 측은 각 층의 정보를 해석해 상위 층으로 전달합니다. 라우터를 지날 때 다음 링크에 맞는 프레임이 만들어지므로 한 프레임이 인터넷 전체를 그대로 이동하는 것은 아닙니다.

패킷 교환에서는 여러 통신이 링크와 큐를 공유합니다. 혼잡으로 대기하거나 버려질 수 있으므로 전송 속도와 실제 완료 시간은 달라집니다. 신뢰성·재전송이 필요한지는 상위 프로토콜의 설계에 따라 달라집니다.

## 주소와 이름의 구분

MAC 주소는 링크에서, IP 주소는 네트워크 전달에서, 포트는 전송 끝점 구분에서 사용됩니다. 도메인은 이름이고 URL에는 스킴·호스트·경로 등이 들어갑니다. 어느 하나만으로 사람의 신원이나 서비스의 안전성을 보장하지 않습니다.
