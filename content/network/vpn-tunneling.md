# VPN과 터널링: IPsec·WireGuard

> **TL;DR**
>
> VPN은 신뢰할 수 없는 네트워크 위에 암호화된 터널을 만들어, 원격 사용자·사이트를 사설망에 안전하게 연결합니다. 터널링은 한 프로토콜의 패킷을 다른 프로토콜에 캡슐화하는 기법이며, IPsec과 WireGuard가 대표적입니다.

## 터널링의 개념

터널링은 원래 패킷을 통째로 다른 패킷의 페이로드로 감싸(캡슐화) 전달하는 것입니다. 공용 인터넷을 지나는 동안 내부 주소·데이터를 감추고, 도착점에서 껍데기를 벗겨(디캡슐화) 원래 패킷을 복원합니다. 계층·캡슐화 개념은 [네트워크 계층과 패킷](layers-packets.md)과 이어집니다.

```
[내부 IP 패킷: 10.0.0.5 → 10.0.0.9]         ← 원래 통신
        │ 암호화 후 캡슐화
        ▼
[외부 IP 패킷: 203.0.113.1 → 198.51.100.2  | 암호문 페이로드]  ← 인터넷을 통과
```

## VPN이 보장하는 것

- **기밀성**: 경로 상의 관찰자가 내용을 못 봄(암호화).
- **무결성**: 변조를 탐지(인증 태그).
- **인증**: 양 끝단이 서로를 검증(키·인증서).

암호 원리는 [TLS·HTTP/2·QUIC](tls-quic.md)와 [암호학](../security/cryptography.md)에서 다룹니다. VPN은 "네트워크에 붙였으니 신뢰"가 아니라 접근 통제의 한 요소일 뿐이며, 이 한계를 다루는 것이 [제로 트러스트](../security/zero-trust.md)입니다.

## 두 가지 대표 기술

| | IPsec | WireGuard |
|---|---|---|
| 계층 | IP 계층(L3) | IP 계층(L3) |
| 구성 | 복잡(IKE 협상, 다양한 옵션) | 단순(공개키 몇 줄) |
| 암호 | 협상형(여러 알고리즘) | 고정된 현대 암호 스위트 |
| 코드 규모 | 큼 | 작음(감사 용이) |

WireGuard는 각 피어를 공개키로 식별하고, 허용된 소스 IP를 키에 매핑합니다.

```ini
# WireGuard 설정 개념 예시 (/etc/wireguard/wg0.conf)
[Interface]
Address = 10.8.0.1/24
PrivateKey = <이 노드의 개인키>
ListenPort = 51820

[Peer]
PublicKey = <상대 공개키>            # 피어를 공개키로 인증
AllowedIPs = 10.8.0.2/32            # 이 키로만 이 내부 IP를 허용(암묵 라우팅+ACL)
Endpoint = 198.51.100.2:51820
```

## 사이트 대 사이트 vs 원격 접속

- **사이트 대 사이트**: 두 지사 네트워크를 게이트웨이끼리 연결해 하나의 사설망처럼.
- **원격 접속(로드 워리어)**: 개인 기기가 회사망에 붙음.
- **스플릿 터널링**: 회사 대상 트래픽만 터널로 보내고 나머지는 로컬로(성능↑, 정책은 신중히).

## 자주 하는 오해

VPN은 익명화 도구가 아니라 신뢰 구간 확장 도구입니다. 또 VPN 연결만으로 내부 자원 접근을 전면 허용하면 침해 시 확산이 커집니다. 접근은 여전히 자원별로 인가해야 합니다.
