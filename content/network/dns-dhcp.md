# DNS와 DHCP: 이름 해석·캐시·주소 임대

> **TL;DR**
>
> DNS는 이름에 대한 정보를 찾고 DHCP는 호스트의 네트워크 설정을 제공하는 프로토콜입니다. DNS 캐시, 권한 서버와 재귀 리졸버, 주소 임대의 역할을 구분해야 합니다.

## DNS 조회의 참여자

애플리케이션은 운영체제나 브라우저의 이름 해석 기능을 이용합니다. 재귀 리졸버는 캐시를 확인하고 필요하면 루트·상위 도메인·권한 서버를 따라 정보를 찾습니다. 권한 서버는 담당 영역의 데이터를 제공하고 리졸버는 사용자를 대신해 결과를 구합니다. 매 요청이 항상 루트부터 시작되는 것은 아닙니다. [RFC 1034](https://www.rfc-editor.org/rfc/rfc1034)

| 레코드 | 의미 |
|---|---|
| A / AAAA | 이름에 대응하는 IPv4 / IPv6 주소 |
| CNAME | 다른 이름에 대한 별칭 |
| MX | 메일 수신 서버 정보 |
| NS | 영역을 담당하는 이름 서버 |
| TXT | 용도에 따라 해석하는 텍스트 데이터 |

DNS는 URL의 경로나 쿼리 전체를 IP 주소로 바꾸는 기능이 아닙니다. 같은 이름도 조회 시점·리졸버·정책에 따라 다른 결과를 받을 수 있습니다.

## 캐시와 TTL

TTL은 레코드를 캐시에 보관할 수 있는 시간에 관여합니다. 운영체제·브라우저·리졸버 등 여러 위치에 캐시가 있어 DNS 변경 직후 모든 클라이언트가 같은 결과를 보는 것은 아닙니다. 이름이 없다는 결과도 캐시될 수 있습니다. TTL이 끝났다는 이유로 기존 TCP 연결까지 자동으로 끊어지는 것도 아닙니다.

## DHCP의 주소 임대

DHCPv4의 초기 할당은 보통 Discover → Offer → Request → ACK 흐름으로 설명합니다. 서버는 주소와 함께 필요한 네트워크 설정을 제공할 수 있고 클라이언트는 임대 갱신을 관리합니다. 재사용·갱신에서는 초기 네 단계와 다른 교환을 사용할 수 있습니다. 다른 서브넷의 서버와 통신하도록 DHCP relay를 구성할 수도 있습니다. [RFC 2131](https://datatracker.ietf.org/doc/html/rfc2131)

IPv6에는 Router Advertisement, SLAAC, DHCPv6 등 별도 메커니즘이 있습니다. DHCPv4 절차를 그대로 적용한다고 가정하지 않습니다.

## 관측과 보안

이름 조회 실패와 주소 할당 실패는 다른 문제입니다. DNSSEC는 데이터의 출처·무결성 검증, DoH·DoT는 특정 구간의 암호화와 관련되므로 역할을 구분합니다. 자세한 보호 관점은 [네트워크 보안](../security/network-security.md)에서 이어집니다.
