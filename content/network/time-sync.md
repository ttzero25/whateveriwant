# 시간 동기화: NTP와 PTP

> **TL;DR**
>
> 분산된 장치들이 공통 시각을 공유하려면 시간 동기화 프로토콜이 필요합니다. NTP는 인터넷 규모에서 밀리초 수준을, PTP는 로컬 네트워크에서 하드웨어 타임스탬프로 마이크로초~나노초 수준을 목표로 합니다.

AI 작성 해설

## 왜 시간 동기화가 필요한가

로그 상관, 인증서 유효성, 분산 트랜잭션 순서, 차량·산업 제어의 협동은 모두 시계가 어긋나면 깨집니다. 각 장치의 수정 발진기는 조금씩 다르게 흐르므로(드리프트), 주기적으로 기준 시각에 맞춰야 합니다. 로그 상관은 [네트워크 진단](troubleshooting.md), 분산 순서는 [분산 시스템](../cs/distributed-systems.md)과 이어집니다.

## NTP: 왕복 지연으로 오프셋 추정

NTP는 계층(stratum) 구조입니다. Stratum 0은 원자시계·GPS, Stratum 1은 그에 직접 연결된 서버, 그 아래로 내려갑니다. 클라이언트는 서버와 타임스탬프를 주고받아 네트워크 왕복을 보정한 오프셋을 계산합니다.

```python
# NTP 오프셋·지연: 4개 타임스탬프로 경로 지연을 상쇄
# t1: 클라 송신, t2: 서버 수신, t3: 서버 송신, t4: 클라 수신
def ntp_offset_delay(t1, t2, t3, t4):
    offset = ((t2 - t1) + (t3 - t4)) / 2   # 내 시계가 서버보다 얼마나 앞/뒤인가
    delay  = (t4 - t1) - (t3 - t2)         # 왕복 네트워크 지연
    return offset, delay

# 경로가 대칭이라는 가정에 기댄다. 비대칭 지연은 오차로 남는다.
```

여러 서버의 표본을 통계로 걸러 튀는 값을 버리고, 시계를 급변(step)이 아니라 서서히 조정(slew)해 단조성을 지킵니다.

## PTP: 하드웨어 타임스탬프로 정밀하게

로컬 네트워크에서 훨씬 높은 정밀도가 필요하면 PTP(IEEE 1588)를 씁니다. 핵심은 소프트웨어가 아니라 **NIC 하드웨어가 패킷 송수신 순간에 타임스탬프**를 찍어, OS 큐잉 지연을 제거하는 것입니다. 스위치가 경로 체류 시간을 보정(투명 클록)하면 나노초 수준까지 갑니다.

| | NTP | PTP |
|---|---|---|
| 범위 | 인터넷 광역 | 주로 로컬/LAN |
| 정밀도 | 밀리초 | 마이크로초~나노초 |
| 타임스탬프 | 소프트웨어 | 하드웨어(가능 시) |

## 자동차·산업에서의 gPTP

차량 네트워크는 센서 융합·제어를 위해 정밀 동기화가 필수라, PTP 프로파일인 gPTP를 씁니다. 이는 차량용 Ethernet의 시간 민감 통신과 이어집니다. [차량용 Ethernet: T1·게이트웨이·타이밍](automotive-ethernet.md)

## 보안 유의점

시간을 속이면 인증서·토큰 만료 판정, 로그 순서, 재생 방지가 무너집니다. NTP는 인증(대칭키·NTS)으로 서버를 검증하고, 신뢰할 수 있는 다중 소스를 씁니다. 만료 판정과 재생 방지는 [암호학](../crypto/foundations.md)·[API 보안](../security/api-security.md)과 통합니다.
