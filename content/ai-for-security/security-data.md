# 보안 데이터: 로그·라벨·특징과 데이터 누출

> **TL;DR**
>
> 보안 모델의 성능은 로그의 품질과 라벨의 의미, 실제 예측 시점에 알 수 있는 정보에 달려 있습니다. 시간과 사건의 경계를 지켜 데이터를 나누고, 미확인 사례를 정상으로 단정하지 않아야 합니다.

AI 작성 해설

## 무엇을 한 개의 샘플로 볼 것인가

| 단위 | 입력의 예 | 라벨의 예 |
|---|---|---|
| 이메일 한 건 | 제목·본문의 표현, 허용된 메타데이터 | 확인된 피싱 / 정상 / 미확인 |
| 로그인 세션 | 실패 횟수, 기기 변경 여부, 접속 시간대 | 검토된 의심 세션 여부 |
| 사용자·시간 구간 | 구간 내 접근량과 자원 종류 | 조사가 필요한 활동 여부 |

샘플 단위가 달라지면 분모와 라벨도 달라집니다. 하나의 사고가 천 개의 로그를 만들 때 로그 정확도와 사고 발견률은 서로 다른 지표입니다.

## 로그에서 특징으로

사건 시각과 수집 시각을 구분하고 시간대, 필드 이름, 자료형을 정규화합니다. 원본 이벤트 ID와 출처를 보존해야 모델의 판단을 원본과 대조할 수 있습니다. 필드가 비어 있는 경우를 정상값 0으로 무조건 치환하지 않습니다. 센서 장애로 생긴 결측과 실제 활동 없음은 다를 수 있습니다.

특징은 예측 시점 이전의 정보로 만듭니다. 오전 10시에 세션을 평가한다면 그 이후 발생한 결과나 하루가 끝나야 알 수 있는 집계값을 사용해서는 안 됩니다. 지연 도착 로그를 실제 서비스가 언제 볼 수 있는지도 맞춰야 합니다.

## 라벨은 사실과 판단 절차를 함께 담는다

“경보가 없었다”는 “정상임을 확인했다”와 다릅니다. 판정 결과와 함께 판정자, 판정 시점, 근거, 확신 정도, 미확인 상태를 남깁니다. 조사 후 라벨이 바뀔 수 있으므로 데이터 버전을 보존합니다.

분석가가 상위 경보만 검토하면 낮은 점수 구간의 정답이 부족해집니다. 이 피드백만으로 재학습하면 기존 모델의 선택을 되풀이할 수 있습니다. 운영 여건에 맞는 표본 검토와 별도 평가 집합으로 이런 편향을 확인합니다.

## 데이터 분할과 누출

| 누출 유형 | 성능이 과장되는 이유 | 방지 방향 |
|---|---|---|
| 미래 정보 | 당시에는 없던 사고 결론을 입력으로 사용 | 예측 시점 기준으로 특징 생성 |
| 사건 중복 | 같은 사고의 유사 로그가 학습·평가에 동시 포함 | 사건·캠페인·개체별 그룹 경계 고려 |
| 전처리 누출 | 평가 데이터 통계로 정규화·특징 선택 | 학습 데이터로만 전처리 학습 |
| 반복적인 시험셋 조정 | 시험 결과에 맞춰 모델을 계속 선택 | 검증셋과 최종 시험셋의 역할 분리 |

시간 분할은 미래 환경 평가에, 그룹 분할은 새 개체·사건으로의 일반화 평가에 도움이 됩니다. 서비스의 배포 상황에 따라 두 조건을 함께 고려합니다. 어떤 분할이든 중복과 특징 생성 시점을 별도로 점검해야 합니다. [scikit-learn: Common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html)

## 데이터 접근과 보존

로그에는 사용자 식별자와 민감한 활동 기록이 포함될 수 있습니다. 목적에 필요한 필드만 수집하고 접근 권한과 보존 기간을 정합니다. 비밀번호·액세스 토큰 같은 비밀을 분석 입력에 남기지 않습니다. 식별자를 가명화해도 다른 필드와 결합하면 개인을 알아볼 수 있으므로 익명화로 단정하지 않습니다. [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

## 클래스 불균형과 재표집

악성이 드문 상황에서는 클래스 가중치로 학습 손실의 비중을 조정하거나 학습 표본을 재구성할 수 있습니다. 두 방법은 경보 임계값 조정과 같은 작업이 아닙니다. 재표집은 학습 분할 안에서만 수행해야 하며 검증·시험의 운영 분포를 임의로 바꾸지 않습니다. 합성 표본도 원래 사건의 독립성을 새로 만들어 주지 않습니다. [imbalanced-learn: Common pitfalls](https://imbalanced-learn.org/stable/common_pitfalls.html)

## 라벨 불확실성과 능동학습

미확인·논쟁 중·확정 라벨을 분리하고 재판정 이력을 남깁니다. 능동학습은 한정된 검토 비용으로 도움이 될 사례를 선택해 라벨을 요청하는 접근입니다. 불확실한 사례만 고르면 대표성이 떨어질 수 있으므로 다양성과 임의 표본 검토를 함께 고려합니다. 검토하지 않은 사건은 자동으로 정상 라벨이 되지 않습니다.

데이터 계보에는 원본 이벤트 → 정규화 → 특징 → 모델 입력의 변환 버전을 남깁니다. 필드가 바뀌었을 때 어떤 모델과 평가 결과가 영향을 받는지 추적할 수 있어야 합니다.
