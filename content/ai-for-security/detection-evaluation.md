# 탐지 모델 평가: 오탐·미탐·기저율과 경보 예산

> **TL;DR**
>
> 드문 보안 사고를 탐지할 때는 정확도만으로 성능을 판단하기 어렵습니다. 정밀도·재현율·오탐률과 실제 경보량을 함께 보고, 분석 인력이 처리할 수 있는 범위에서 임계값을 선택합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 혼동 행렬부터 읽기

여기서는 실제 악성을 양성으로, 경보 발생을 양성 예측으로 정의합니다. 실제 라벨이 불완전하면 이 지표도 그 한계를 물려받습니다.

| 실제 상태 | 경보 발생 | 경보 없음 |
|---|---|---|
| 악성 | TP: 실제 탐지 | FN: 미탐 |
| 정상 | FP: 오탐 | TN: 정상 판정 |

정밀도 Precision = TP / (TP + FP)는 경보 중 실제 악성의 비율입니다. 재현율 Recall = TP / (TP + FN)은 실제 악성 중 발견한 비율입니다. 오탐률 FPR = FP / (FP + TN)은 정상 중 경보가 된 비율입니다. **1 − 정밀도와 오탐률은 분모가 다릅니다.** [Google ML Crash Course: Classification metrics](https://developers.google.com/machine-learning/crash-course/classification/accuracy-precision-recall)

## 기저율이 낮으면 무슨 일이 생기는가

다음은 실측 성능이 아닌 가상 계산입니다. 하루 100,000건 중 실제 악성이 100건이라고 가정합니다. 재현율 90%, 정상에 대한 오탐률이 약 1%인 모델은 다음 결과를 냅니다.

| 결과 | 건수 |
|---|---|
| 실제 악성 중 경보 TP | 90 |
| 놓친 악성 FN | 10 |
| 정상인데 경보 FP | 999 |
| 정상이고 경보 없음 TN | 98,901 |

경보는 1,089건이고 정밀도는 90 / 1,089 ≈ **8.3%**입니다. 경보 대부분이 정상인 셈입니다. 정확도는 약 99.0%지만 분석가는 실제 악성 90건을 찾기 위해 많은 경보를 검토해야 합니다. 모든 건을 정상이라고만 예측해도 정확도는 99.9%가 되며 이때 재현율은 0%입니다.

실제 악성의 비율인 기저율이 달라지면 같은 재현율·오탐률에서도 정밀도가 바뀝니다. 정상과 악성을 반씩 섞은 시험셋의 정밀도를 실제 운영의 경보 품질로 그대로 해석하면 안 됩니다.

## 임계값과 경보 예산

일반적인 점수 기반 모델에서는 임계값을 낮추면 더 많은 이벤트를 경보로 올려 재현율이 높아질 수 있지만 오탐도 늘어납니다. 검증 데이터에서 여러 임계값을 비교하고 최종 시험 데이터로 선택 결과를 평가합니다.

하루 검토 가능량이 200건이라면 전체 분류 성능 외에 상위 200건의 정밀도와 그 범위에서 놓치는 사고를 봅니다. 이벤트 중복을 사건 단위로 묶은 이후에도 경보량과 발견률을 다시 측정합니다. 위험 점수 0.9가 항상 악성 확률 90%를 뜻하는 것은 아닙니다. 확률로 사용할 계획이면 별도의 보정과 검증이 필요합니다.

## 지표를 운영 목표와 연결하기

| 평가 항목 | 확인하는 것 |
|---|---|
| PR 곡선 | 여러 임계값에서 정밀도와 재현율의 관계 |
| ROC 곡선 | 재현율과 오탐률의 관계; 낮은 오탐률 구간도 별도 확인 |
| 사건별 발견률·탐지 지연 | 실제 사고를 얼마나 빠짐없이, 빨리 발견했는가 |
| 경보 수·검토 시간 | 분석가 업무량이 처리 가능한가 |
| 환경별 결과 | 부서·장비·기간에 따라 성능이 치우치는가 |

작은 평가 집합의 단일 점수는 불안정할 수 있습니다. 표본 수와 악성 사례 수를 함께 보고하고, 독립 사건 단위를 고려한 신뢰구간과 기간별 결과로 불확실성을 드러냅니다.

## PR-AUC와 확률 보정

PR 곡선의 요약에는 계산 방식이 중요합니다. Average precision(AP)은 재현율 증가량으로 정밀도를 가중하는 요약이고, 사다리꼴 적분으로 구한 PR 면적과 항상 같지는 않습니다. 비교 시 지표 정의·양성 비율·평가 집합을 함께 고정합니다.

보정은 점수 0.8인 사례 집단에서 실제 양성이 약 80%인지처럼 확률의 경험적 일치를 다룹니다. 순위를 잘 매기는 것과 보정이 좋은 것은 다릅니다. 보정에 사용할 데이터를 학습·평가 경계에 맞게 나누고, reliability diagram과 확률 손실을 함께 봅니다. [scikit-learn: Probability calibration](https://scikit-learn.org/stable/modules/calibration.html)

## 비용과 사건 단위의 평가

예를 들어 총 비용을 C_FP·FP + C_FN·FN + 검토 비용으로 정의할 수 있습니다. 실제 비용이 일정하지 않다면 자산·사건별 가중치와 운영 제약을 명시합니다. 검증 데이터에서 정책을 고르고 최종 시험 데이터로 평가합니다.

하나의 사건에서 경보가 100번 울린 것을 실제 사고 100건 발견으로 세지 않습니다. 이벤트별 지표와 함께 사건별 발견 여부·첫 탐지 지연·중복률을 기록합니다. 판정 완료된 경보만 평가하면 미탐을 추정하기 어렵다는 한계도 표시합니다.
