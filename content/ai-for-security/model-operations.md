# 보안 모델 운영: 관측·재학습·롤백

> **TL;DR**
>
> 보안 모델의 배포 단위에는 가중치뿐 아니라 특징 생성·전처리·임계값·데이터 스키마가 포함됩니다. 성능 변화를 관측하고 검증한 후보만 배포하며 이전 상태로 돌아갈 경로를 유지합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 무엇을 함께 버전으로 묶는가

| 구성 요소 | 재현에 필요한 정보 |
|---|---|
| 데이터·라벨 | 범위·출처·분할·판정 기준 |
| 특징·전처리 | 스키마·결측 처리·스케일링 |
| 모델 | 학습 코드·설정·아티팩트 식별자 |
| 의사 결정 | 임계값·경보 묶기·예외 정책 |
| 운영 | 승인·배포·복구·관측 설정 |

가중치만 롤백하고 전처리는 새 버전으로 남겨 두면 검증했던 입력·모델 조합이 아닐 수 있습니다. [OWASP Secure AI Model Ops](https://cheatsheetseries.owasp.org/cheatsheets/Secure_AI_Model_Ops_Cheat_Sheet.html)

## 무엇이 바뀌었는지 구분하기

입력 결측·분포·스키마, 점수 분포, 경보량, 판정 완료 사례의 성능을 각각 관측합니다. 데이터 드리프트는 성능 저하의 단서일 수 있지만 그 자체가 성능 저하의 증명은 아닙니다. 라벨 지연을 감안해 평가 기간과 판정 완료율을 함께 표시합니다.

## 재학습은 자동 정답이 아니다

최근 데이터를 무조건 정상으로 흡수하면 실제 이상 행동도 기준에 포함될 수 있습니다. 데이터 검토 후 후보 모델을 만들고, 고정 회귀 집합과 최근 대표 데이터에서 비교합니다. 후보를 평가하는 기준은 성능·지연·비용·권한 경계와 중요한 사건의 회귀를 포함합니다.

## 단계적인 배포

먼저 shadow mode에서 실제 입력의 점수와 지연을 관측하고, 제한된 범위로 적용해 운영 영향을 확인합니다. 라벨이 없으면 shadow mode만으로 실제 재현율을 확정할 수 없습니다. 중단 기준과 롤백 담당자를 사전에 정하며 모델 실패 시 기존 규칙이나 수동 검토로 전환할 조건을 마련합니다.

## 확인 질문

경보량이 절반이 된 것이 좋은 변화인지 판단하려면 무엇을 더 알아야 할까요? 입력 수집 상태, 임계값, 실제 사건의 미탐을 나누어 보세요.
