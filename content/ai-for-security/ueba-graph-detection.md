# UEBA와 그래프 기반 탐지

> **TL;DR**
>
> UEBA는 사용자·엔티티의 평소 행동 기준선을 학습해 이탈을 탐지하고, 그래프 기반 탐지는 계정·호스트·자원을 노드로 연결해 개별 이벤트로는 안 보이는 경로(횡적 이동 등)를 드러냅니다. 둘 다 "이상 ≠ 악성"을 전제로 맥락을 붙여야 합니다.

AI 작성 해설

## 왜 행위 기준선인가

시그니처는 알려진 악성만 잡습니다. 내부자 위협·탈취된 정상 계정은 "허가된 행동"이라 규칙을 통과합니다. UEBA(User and Entity Behavior Analytics)는 각 주체의 평소 패턴(로그인 시간·위치·접근 자원·데이터량)을 학습해, 그 주체 기준으로 이탈을 점수화합니다. 로그 이상 탐지의 기초는 [로그 이상 탐지와 드리프트](log-anomaly-detection.md)와 이어집니다.

## 기준선과 피어 그룹

핵심은 "전체 평균"이 아니라 **그 주체 자신** 또는 **비슷한 역할 그룹(peer group)**과 비교하는 것입니다. 개발자에게 정상인 심야 배포가 회계 담당에겐 이상 신호일 수 있습니다.

```python
# 개념 예시: 사용자별 기준선 대비 이탈을 견고한 z-점수로
import statistics

def robust_z(value: float, history: list[float]) -> float:
    med = statistics.median(history)
    mad = statistics.median([abs(x - med) for x in history]) or 1e-9  # 중앙값 절대편차
    return 0.6745 * (value - med) / mad     # 이상치에 강한 표준화

# 예: 오늘 다운로드량이 이 사용자의 과거 분포에서 얼마나 벗어났는가
score = robust_z(today_bytes, past_30_days_bytes)
# 여러 신호(시간·위치·자원)의 점수를 합쳐 위험도를 만든다 (단일 신호로 단정 금지)
```

평균·표준편차 대신 중앙값 기반을 쓰는 이유는, 과거에 섞인 이상치가 기준선을 오염시키지 않게 하기 위함입니다.

## 그래프로 보는 관계

개별 이벤트는 정상이어도, 연결하면 위험한 경로가 드러납니다. 계정·호스트·자원을 노드로, 로그인·접근·권한 부여를 간선으로 만든 그래프에서:

- **횡적 이동**: A 계정이 평소 안 가던 호스트들을 연쇄로 접근하는 경로.
- **권한 상승 경로**: 저권한에서 고권한 자원까지 이어지는 도달 가능 경로.
- **공유 인프라**: 여러 의심 계정이 같은 IP·자원을 공유하는 군집.

그래프 탐색·최단 경로·연결 요소는 [그래프와 탐색](../algorithms/graphs-search.md)의 알고리즘을 그대로 씁니다. 그래프 신경망(GNN)으로 노드를 분류하기도 합니다.

## "이상"에 맥락을 붙인다

이상 탐지의 최대 함정은 오탐 폭증입니다. 이상 점수 하나로 경보를 내지 말고, 자산 중요도·다른 신호·최근 변경(신규 프로젝트·조직 개편)을 함께 봐 우선순위를 매깁니다. 기저율 문제와 경보 예산은 [탐지 지표와 경보 예산](detection-evaluation.md)에서 다룹니다.

## 확인 질문

이 이탈이 그 사용자·피어 그룹 기준으로도 이상한가요, 아니면 전체 평균 기준일 뿐인가요? 개별로는 정상인 이벤트들을 연결했을 때 위험한 경로가 보이나요?
