# 그리디 알고리즘

> **TL;DR**
>
> 그리디는 매 단계에서 지금 가장 좋아 보이는 선택을 하고 되돌리지 않습니다. 문제가 "탐욕적 선택 속성"과 "최적 부분 구조"를 가질 때만 전역 최적을 보장하며, 아니면 근사해에 그칩니다.

AI 작성 해설

## 아이디어와 전제

그리디는 지역 최적 선택을 반복해 전역 해를 만듭니다. 빠르고 단순하지만, **항상 옳지는 않습니다.** 옳으려면 두 조건이 필요합니다: 지역 최적 선택이 전역 최적의 일부가 되고(탐욕적 선택 속성), 부분 문제의 최적이 전체 최적을 구성해야 합니다(최적 부분 구조). 설계 패러다임 비교는 [동적 계획법과 알고리즘 설계](dynamic-programming.md)에서 다룹니다.

## 되는 예: 회의실 배정

가장 일찍 끝나는 회의를 반복 선택하면 최대 개수의 겹치지 않는 회의를 고를 수 있습니다(증명 가능).

```python
def max_meetings(intervals):
    intervals.sort(key=lambda x: x[1])   # 끝나는 시간 기준 정렬
    count, end = 0, float("-inf")
    for s, e in intervals:
        if s >= end:                     # 지금 회의가 이전 것과 안 겹치면
            count += 1; end = e          # 선택하고 되돌리지 않음
    return count
```

## 안 되는 예: 동전 거스름돈

일부 동전 체계에서는 큰 동전부터 고르는 그리디가 최적이지만, 임의 체계(예: 1, 3, 4로 6을 만들기)에서는 그리디(4+1+1=3개)가 최적(3+3=2개)을 놓칩니다. 이때는 [동적 계획법](dynamic-programming.md)이 필요합니다. 즉 "그리디로 풀 수 있는가"를 먼저 따져야 합니다.

## 대표 그리디 알고리즘

| 문제 | 그리디 기준 |
|---|---|
| 최소 신장 트리(크루스칼) | 가장 가벼운 간선부터, 사이클 없이 |
| 다익스트라 | 가장 가까운 미확정 정점부터 확정 |
| 허프만 부호화 | 빈도 낮은 두 노드를 반복 병합 |
| 활동 선택 | 가장 일찍 끝나는 것부터 |

크루스칼·다익스트라는 [그래프와 탐색](graphs-search.md), 우선순위 선택은 [힙과 우선순위 큐](heaps-priority-queues.md)와 이어집니다.

## 옳음을 어떻게 확신하나

그리디의 정당성은 대개 "교환 논증"으로 증명합니다: 최적해에서 그리디 선택과 다른 부분을 그리디 선택으로 바꿔도 나빠지지 않음을 보입니다. 증명 없이 그리디를 쓰면 미묘한 반례에 걸리기 쉽습니다.
