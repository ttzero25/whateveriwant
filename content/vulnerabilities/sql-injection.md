# SQL Injection: 데이터와 쿼리의 경계

> **TL;DR**
>
> 외부 입력을 SQL 구조에 섞으면 데이터가 쿼리의 의미를 바꿀 수 있습니다. 값은 바인딩하고 쿼리 구조는 애플리케이션이 결정해야 합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 발생 원리와 영향

검색·필터 입력을 문자열로 붙여 SQL을 만들 때 신뢰 경계가 무너집니다. 영향은 DB 계정 권한과 실행 경로에 따라 정보 노출·변조 등으로 달라집니다.

## 가상 사례로 이해하기

가상 도서 검색 서비스에서 제목 검색은 문자열 값만 받아야 합니다. 정렬 기준은 서버가 정한 열 목록에서 선택해야 하며, 입력 전체를 SQL 문법으로 취급하면 안 됩니다.

## 예방과 수정

- 매개변수화된 쿼리로 값과 SQL 문법을 분리합니다.
- 열 이름·정렬 방향처럼 값 바인딩 대상이 아닌 부분은 서버 측 허용 목록으로 선택합니다.
- 애플리케이션 DB 계정의 읽기·쓰기 범위를 업무에 필요한 수준으로 제한합니다.

## 수정 후 확인할 조건

작은따옴표가 포함된 정상 제목도 검색되는지, 모든 쿼리 경로가 같은 바인딩 규칙을 쓰는지 확인합니다. ORM을 사용해도 raw SQL 경로는 따로 검토합니다.

## 자주 하는 오해

입력에서 몇 글자를 지우는 것과 데이터·코드 경계를 지키는 것은 다릅니다. 준비된 문장 안에서 다시 동적 SQL을 만들면 별도 위험이 남습니다.
