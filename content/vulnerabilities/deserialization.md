# 안전하지 않은 역직렬화: 데이터와 객체 복원

> **TL;DR**
>
> 외부 데이터를 복원할 때 임의 객체나 동작까지 만들 수 있으면 위험합니다. 필요한 데이터 구조만 허용하고 복원 과정의 부작용을 제한합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 발생 원리와 영향

일부 직렬화 형식은 타입 정보와 객체 수명주기 동작을 함께 다룹니다. 외부 데이터를 신뢰하고 복원하면 권한 없는 상태 변경·자원 고갈·코드 실행 같은 영향이 가능해집니다.

## 가상 사례로 이해하기

가상 작업 큐에는 작업 이름과 정해진 매개변수만 필요합니다. 소비자가 임의 타입을 생성하게 두기보다 허용된 스키마를 읽고 서버가 작업을 선택하도록 설계합니다.

## 예방과 수정

- 신뢰하지 않는 입력에 네이티브 객체 역직렬화를 적용하지 않는 설계를 우선합니다.
- 단순 데이터 형식과 명시적 스키마·타입 허용 목록을 사용합니다.
- 메시지 무결성·송신 권한과 함께 깊이·크기·처리 시간을 제한합니다.

## 수정 후 확인할 조건

정의된 스키마만 수용하며 알 수 없는 타입·필드가 정책에 맞게 거절되는지 확인합니다. 오류 후에도 작업 큐와 소비자의 상태가 일관되는지 검토합니다.

## 자주 하는 오해

JSON이라는 이름만으로 안전이 보장되지는 않습니다. 읽은 데이터로 동적 타입을 만들거나 다른 실행 경로에 넘기면 별도 검증이 필요합니다.
