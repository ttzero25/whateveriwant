# 접근 제어 실패: IDOR·BOLA·권한 경계

> **TL;DR**
>
> 인증된 사용자도 모든 객체와 기능에 접근할 수 있는 것은 아닙니다. 서버는 요청마다 주체·대상·행동·조직 경계를 확인해야 합니다.

AI 작성 해설 · 소유자 검토 전 · 출처 확인: 2026-09-10

## 발생 원리와 영향

IDOR는 객체 참조에 대한 권한 확인 누락을, BOLA는 API의 객체 수준 인가 실패를 설명할 때 쓰입니다. 같은 역할 사이의 타인 데이터 접근은 수평 권한 문제, 상위 역할 기능 접근은 수직 권한 문제입니다.

## 가상 사례로 이해하기

가상 문서 서비스에서 사용자 A는 자신에게 공유된 문서만 읽을 수 있습니다. 로그인 확인 뒤 문서 번호만으로 조회하면 공유 관계와 조직 경계가 빠질 수 있습니다.

## 예방과 수정

- 기본 거부 정책을 두고 서버에서 모든 요청의 객체·기능 권한을 확인합니다.
- 조회·수정·삭제·내보내기 경로에 일관된 정책을 적용합니다.
- 데이터 조회 범위에 조직·소유 관계를 반영하고 권한 변경과 캐시 무효화를 연결합니다.

## 수정 후 확인할 조건

테스트용 두 사용자와 두 조직에 대해 허용·거절 행렬을 작성합니다. 같은 객체의 조회가 허용되어도 수정은 거절되어야 하는 경우를 포함합니다.

## 자주 하는 오해

예측하기 어려운 UUID는 권한 검사를 대체하지 않습니다. UI에서 버튼을 숨기는 것도 서버 측 인가가 아닙니다.
