## 먼저 구분하기

약점은 잘못된 설계·구현의 유형이고, 실제 취약점은 특정 제품·환경에서 보안 요구를 깨는 문제입니다. CWE는 약점 유형을, CVE는 공개된 취약점 레코드를 식별할 때 사용합니다. 같은 유형이 여러 제품에 나타날 수 있습니다.

OWASP Top 10은 웹 애플리케이션 위험을 설명하는 인식 제고 자료입니다. 이 컬렉션은 Top 10의 순위를 복제한 목록이 아니라 웹·API·시스템의 대표 약점을 묶은 학습 과정입니다. 모든 취약점 유형을 망라하지 않습니다. [OWASP Top 10](https://owasp.org/Top10/) · [CWE](https://cwe.mitre.org/) · [CVE](https://www.cve.org/)

## 목적별 읽기

- 웹·API 개발: SQL Injection → XSS → CSRF → 접근 제어 → 인증·세션
- 백엔드와 파일 처리: SSRF → 파일 처리 → 명령 주입 → XXE → SSTI → 역직렬화
- 웹 프론트·경계: 오픈 리다이렉트 → 클릭재킹 → 프로토타입 오염 → 요청 스머글링
- 시스템 개발: 메모리 안전성 → 정수 오버플로 → 경쟁 상태 → 설정 오류
- 처음 보는 용어 확인: [한영 용어집](glossary.md)

## 한 가지 사례를 정리하는 틀

| 항목 | 기록할 내용 |
|---|---|
| 보호할 대상 | 데이터·권한·서비스 가용성 |
| 신뢰 경계 | 외부 입력이 들어오는 지점과 실행·저장 지점 |
| 실패한 조건 | 빠진 검증, 과한 권한, 깨진 수명·동시성 규칙 |
| 수정 | 원인을 제거하는 설계·구현 변경 |
| 검증 | 정상 기능 유지와 허용하지 않은 동작의 거절 |
| 운영 | 배포 범위·관측·되돌리기 계획 |

예시는 학습용 가상 서비스이며 실제 제품에서 취약점이 확인되었다는 의미가 아닙니다. 검증 항목은 자신이 관리하는 코드의 리뷰·단위 테스트·통합 테스트에 적용할 수 있는 방어 요구사항입니다.

## 우선순위는 환경과 함께 판단하기

CVSS는 기술적 심각도를 표현하는 체계입니다. 점수 하나가 조직의 수정 우선순위 전체를 결정하지는 않습니다. 노출 범위, 도달 가능한 코드 경로, 자산 중요도, 기존 통제를 함께 확인합니다. [FIRST: CVSS](https://www.first.org/cvss/)
