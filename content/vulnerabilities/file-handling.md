# 파일 처리 취약점: 경로 순회와 업로드

> **TL;DR**
>
> 사용자가 고른 파일 이름·경로·형식을 서버의 저장 위치나 실행 권한으로 바로 연결하면 안 됩니다. 접근 범위와 파일 처리 권한을 따로 제한합니다.

AI 작성 해설

## 발생 원리와 영향

경로 순회는 파일 접근이 허용된 디렉터리 밖으로 나가는 문제입니다. 업로드 취약점은 저장 위치, 실행 가능성, 파서의 처리 범위가 맞물립니다. 읽기 권한과 업로드 권한도 서로 다릅니다.

## 가상 사례로 이해하기

가상 첨부 서비스는 외부 파일 이름을 화면 표시용으로만 쓰고, 내부 저장 키는 서버가 생성합니다. 내려받을 때도 파일 소유·공유 권한을 다시 확인합니다.

## 예방과 수정

- 파일 ID를 서버가 관리하는 저장 키에 매핑하고 정규화 후 허용 범위를 검증합니다.
- 확장자·콘텐츠 형식·크기 등을 함께 검증하고 실행 가능한 위치와 업로드 저장소를 분리합니다.
- 압축 해제 후 크기와 파일 수를 제한하고, 파일 처리기를 낮은 권한으로 격리합니다.

## 수정 후 확인할 조건

승인된 문서 형식과 한도 내 크기는 처리되고 정책 밖 형식은 거절되는지 확인합니다. 저장·변환·다운로드 전 과정의 경로와 접근 정책을 검토합니다.

## 자주 하는 오해

클라이언트가 선언한 MIME 유형만으로 실제 파일 내용을 신뢰할 수 없습니다. 경로 문자열 검사만으로 심볼릭 링크와 동시 변경까지 해결되는 것도 아닙니다.

## 확인 질문

파일 업로드에 로그인만 요구하면 다른 사용자의 첨부 파일 읽기도 막을 수 있을까요?
